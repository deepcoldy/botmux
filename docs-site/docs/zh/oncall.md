# Oncall 模式

<video src="img/video-v6-oncall-voice.mp4" controls preload="metadata" style="width:100%;border-radius:8px"></video>

把机器人拉进值班群、报警群或答疑群，给它绑定一个项目目录。之后群里**任何成员**都能直接 @ 它提问，不用选仓库，也不用先申请授权，机器人会在这个目录里回答。

适合「人多、随时问、问的都是同一个项目」的群：值班群、报警群、跨团队答疑群。

> **把 bot 拉进群，不等于放开对话。** 只有绑定 oncall 之后（或用裸 `/grant` 整群放开），群里所有人才能和它对话。没绑也没授权时，名单外的人 @ 它会被拦下，并弹出授权申请卡。详见[权限与授权 · 入群不等于授权](/permissions#入群不等于授权)。

## 开启后有什么变化

| | 绑定前 | 绑定后 |
|---|---|---|
| 谁能 @ 机器人对话 | 只有 owner、管理员（`allowedUsers`）和被授权的人 | 群里**所有人**，包括群里的其它机器人 |
| 消息额度 | 授权卡放进来的访客有额度限制 | **不限额** |
| 新话题从哪个目录开始 | 弹仓库选择卡，或用 Bot 的默认目录 | 直接进入绑定目录 |
| 谁能改会话状态（`/cd`、`/restart`、`/close`、点卡片按钮） | owner / 管理员 | 仍然只有 owner / 管理员 |

绑定**按 bot 计**：一个群里有好几个机器人时，只有绑定过的那个会对全群开放。

## 怎么开启（三选一）

| 想要… | 用这个 |
|---|---|
| 在某个群里马上用起来 | 方式一：群里发 `/oncall bind` |
| 在网页上逐个群开 | 方式二：Dashboard「群组管理」 |
| 让这个 bot 进的每个群都自动开 | 方式三：Dashboard「Bot 配置」 |

### 方式一：群里发命令

在群里 @ 机器人发一句：

```
/oncall bind ~/projects/your-service
```

- 只绑当前被 @ 的这个 bot。想一次绑多个：`@bot1 @bot2 /oncall bind <目录>`。
- 目录不存在时会自动创建。
- 需要操作权（owner / `allowedUsers`）。
- 绑定后，本群**下一个新话题**起就直接用这个目录。

### 方式二：Dashboard「群组管理」按群开启

1. 打开 Dashboard 的「**群组管理**」页，找到这个群，点「**管理**」。
2. 切到「**机器人设置**」标签，在左侧选中要开的机器人。
3. 在「**Oncall 模式**」一栏点「**启用**」，填上工作目录，点「**保存**」。

只影响这一个群里的这一个机器人。这里填的目录必须已经存在。取消「启用」再保存就是解绑。

![群组管理 · 机器人设置里的 Oncall 模式](/img/oncall-group-manage-bots.png)

### 方式三：Dashboard「Bot 配置」所有群自动开启

打开「**Bot 配置**」页，选中机器人，在「**默认工作目录**」里选「**Oncall 值班模式**」，填一个目录，点「**保存**」。

这个区块是三选一：

| 选项 | 效果 |
|---|---|
| 每次手动选仓库（默认） | 新会话先在飞书里弹仓库选择卡 |
| 固定进默认目录 | 新会话直接进这个目录，权限不变 |
| **Oncall 值班模式** | 群自动绑定到这个目录，并对全群开放对话 |

选了 Oncall 值班模式之后：

- **自动绑定的时机**：机器人在某个群里第一次收到消息时，如果这个群还没绑定，就自动绑到这个目录。新群、老群都一样，绑定发生在权限判断之前，所以第一个开口的人（或报警机器人）不会被弹授权卡。
- **已经绑定的群不会被改**，不管是手动绑的还是别的 bot 绑的。
- **解绑过的群（`/oncall unbind` 或在 Dashboard 里取消启用），不会再被自动绑回去。** 想重新绑，在群里发 `/oncall bind <目录>`。
- **私聊和其它会话也用这个目录**：这个 bot 的私聊、话题等新会话，也会默认从这里开始（但私聊不会因此对所有人开放）。
- **切回另外两个选项时**，之前自动绑上、且仍指向这个目录的群会一起解绑；你手动绑到其它目录的群保留不动。

机器人卡片上会显示「当前绑定 N 个群 · 自动绑定过 M 个群」。「自动绑定过」是自动绑定名单的大小，不是当前绑定数：解绑过、或切换模式时被释放的群也算在里面，这些群都不会再被自动绑定。

## 命令

| 命令 | 作用 |
|---|---|
| `/oncall bind <目录>` | 把当前 bot 在本群绑到这个目录；已绑定时改成新目录。多个 bot：`@bot1 @bot2 /oncall bind <目录>` |
| `/oncall unbind` | 解除当前 bot 在本群的绑定，之后新话题恢复仓库选择卡 |
| `/oncall status` | 查看当前 bot 在本群绑的目录（只发 `/oncall` 也一样） |

- 子命令也可以写中文：`绑定`、`解绑`、`状态`。
- 三条命令都要在群里用，都需要操作权。
- 私聊专属群（私聊时自动建出的会话群）的绑定由机器人建群时写好，不支持用 `/oncall` 改。用 `/g` 建的群不受此限，可以正常用 `/oncall`。
- 绑定后在会话里用 `/cd <目录>` 换目录，仍然保持 oncall 模式。

## 权限怎么分

- **对话**：群里所有人都能问问题、查日志、读代码，不限额。被拉黑（`blockedUsers`）的人依然会被拦。
- **管理**：切目录、重启、关闭会话、点流式卡片按钮，仍然只有 owner / 管理员能做，防止群成员误操作把会话搞乱。
- **想给群成员开放个别低风险命令**：在「Bot 配置」里把命令加进「canTalk 可用的 daemon 命令」（对应 `bots.json` 的 `canTalkDaemonCommands`），比如 `/status /help`。`/cd`、`/restart` 这类会改状态的命令不建议放开。

> Oncall 绑定**不限制文件访问**。想让群成员碰不到密钥和其它仓库，再开[文件沙盒](/sandbox)的白名单隔离（工作目录仍可写，改动直接落到本机）。想让改动不进主分支，用 `/tw` 在独立 worktree 里开话题。

## 回复会 @ 谁

oncall 群里，机器人的回复卡片底部「发送给：」会 @ **这一轮提问的人**，谁问的就提醒谁。如果提问的是另一个机器人，就改为 @ owner，避免两个机器人互相 @ 起来。

## 搭配定时任务

在 oncall 群里发：

```
/schedule 每天9:00 检查昨天的报警趋势并总结
```

机器人每天定点把报告发到群里，人不在也有人看着。定时任务会沿用本群绑定的目录。更多写法见[定时任务](/schedule)。

## 手动编辑 `bots.json`

Dashboard 里的设置都写在 `bots.json` 里，也可以手动改：

```json
{
  "oncallChats": [
    { "chatId": "oc_xxx", "workingDir": "~/projects/your-service" }
  ],
  "defaultOncall": { "enabled": true, "workingDir": "~/projects/your-service" }
}
```

- `oncallChats`：按群的绑定列表，每项是群 ID 和目录。
- `defaultOncall`：对应「Oncall 值班模式」。
- `defaultOncallAutoboundChats`：自动绑定名单，由 botmux 自己维护，一般不用手改。

其它字段见 [bots.json 配置](/bots-json)。

## 常见问题

**开了 Oncall 值班模式，某个群还是没自动绑上？**
- 这个群以前解绑过（`/oncall unbind` 或在 Dashboard 里取消启用），或者在切换模式时被释放过。在群里发 `/oncall bind <目录>` 重新绑。
- 配置的目录在机器上不存在，自动绑定会跳过。先把目录建好。

**想让整个群都能对话，但不想换目录？**
用裸 `/grant` 整群放开即可，见[权限与授权](/permissions)。
