# @ 策略（mention-mode）

在普通群里，bot 默认只回应**明确 @ 它**的消息。「@ 策略」决定什么时候可以不用 @。

它只管「这条消息是不是在叫这个 bot」，**不管权限**：免 @ 不等于免授权，没有对话权的人照样会被拦（见[权限与授权](/permissions)）。

## 先选一个模式

| 模式 | Dashboard 里的名字 | 效果 | 适合 |
|------|------|------|------|
| `always`（默认） | 必须 @ | 每次都要 @ 本 bot 才回 | 大群，最安静 |
| `topic` | 话题内免 @ | 顶层消息仍要 @；在**本 bot 已接管的话题**里回复不用再 @ | 话题里反复追问 |
| `never` | 全群免 @ | 群里有对话权的人发什么都回，包括没 @ 的顶层新消息（会直接新建或续接会话） | 专人专用群、值班群 |
| `ambient` | 免 @，让位 | 和 `never` 一样免 @；但如果消息 **@ 了别的成员（人或 bot）而没 @ 本 bot**，就保持安静，因为那是在叫别人 | 多 bot / 多人协作群里的「默认应答者」 |

补充两点：

- `@所有人` 不算「叫别人」，`ambient` 下照样回应。
- `topic` 模式下，在话题里回复时如果只 @ 了别人，bot 同样会让路。

## 怎么设置

@ 策略有两层，**群级设置优先**：

| 层级 | 作用范围 | 在哪改 |
|------|------|------|
| Bot 默认 | 这个 bot 所在的所有普通群 | Dashboard「Bot 配置 → 会话 → 群聊回复条件」，或 [bots.json](/bots-json) 的 `regularGroupMentionMode` |
| 单个群 | 只影响当前这个群 | 在群里发 `/mention-mode`（写入 bots.json 的 `chatMentionModes`） |

![Dashboard 的「群聊回复条件」设置](/img/mention-mode-dashboard.png)

### 在群里用命令改

在普通群里发（多 bot 群要 @ 到具体那个 bot）：

```text
@bot /mention-mode status     # 查看当前群用的是哪种
@bot /mention-mode always
@bot /mention-mode topic
@bot /mention-mode never
@bot /mention-mode ambient
```

- 查看（`status` 或不带参数）：有对话权即可。
- 修改：需要**操作权**（owner / `allowedUsers`）。
- 改完立即生效，只影响这个群，不动 bot 默认值。
- 把群设成和 bot 默认相同的值，等于「恢复跟随默认」：以后 bot 默认改了，这个群也跟着变。（开了 `signedChatDefaults` 的 bot 例外：设置会原样保存，见文末「可信建群服务」。）

### 哪些群能设

只有**普通群**能设：

- 私聊：天然不需要 @。
- 话题群：本来就是话题形态，命令会回复「无需设置」。
- `/group` 建出来的会话群：由 bot 自动管理，拒绝修改。

## 为什么设了 always，它不 @ 也回？

「必须 @」是默认主规则，但还有一组并列的例外，命中任意一条就会回应。觉得「它怎么不听话」时，基本是下面这些情况：

| # | 情况 | 说明 |
|---|------|------|
| 1 | 续接本 bot 的话题回复 | 这条回复所在的话题已经确定是冲着本 bot 来的（比如话题内回复被折回群会话），直接放行 |
| 2 | 替身触发 | bot 开了替身模式，消息 @ 了被代答的对象（见下文「替身模式」） |
| 3 | 消息监听命中 | Dashboard「消息监听」里配的[监听规则](/bots-json#message-listener)匹配了。这条**不看 @ 策略，也不走常规对话权限**，监听器有自己的发送者过滤 |
| 4 | 模式是 `never` | bot 默认或本群被设成了全群免 @ |
| 5 | 模式是 `ambient`，且消息没 @ 别人 | |
| 6 | 模式是 `topic`，且消息在本 bot 接管的话题里 | |
| 7 | 免 @ 斜杠命令 | 在 Dashboard「Bot 配置 → 会话 → 免@ 斜杠命令」里列出的命令（比如 `/solve`），在普通群里裸发也会触发。只放开列出的命令，不是全群免 @ |
| 8 | 内置免 @ 命令 | `/dash` 和 `/dashboard link` 在任何群里都不用 @ |
| 9 | 群负责人 | 本 bot 被设成了这个群的负责人（默认接待者），群里**顶层**未 @ 消息由它接。需要先在「Bot 配置 → 会话」里打开「群负责人（默认接待者）」。详见[斜杠命令](/slash-commands)里的「群负责人」一节 |
| 10 | 1 人 1 bot 群 | 群里只有你和这个 bot，默认不用 @。可以关掉，见下一节 |

几点细节：

- 除了消息监听（第 3 条），其它情况都要求发送者**有对话权**。
- 第 7、8、9 条也遵守「点名让路」：消息开头先 @ 了别人，bot 不接。但 `/solve @某人` 这种 @ 写在命令后面的，算命令参数，照常触发。
- 多 bot 群里想避免互相抢话，优先用 `ambient`：谁被点名谁回答。

> 小提示：发出去才发现忘了 @？用飞书消息菜单里的「修改」补上 @ 本 bot，同样能触发。

## 替身模式：@ 某人时由 bot 代答

替身模式让 bot 当某些人的「替身」：群里有人 @ 了这些人（没 @ bot），bot 会代他们回答。适合值班人、项目负责人这类经常被 @ 提问的人。

### 怎么开

在 Dashboard「Bot 配置 → 会话 → 替身模式」里打开「启用替身触发」，再添加替身对象。保存后立即生效。

- 替身对象可以直接填邮箱，保存时会自动解析成本应用的 Open ID；解析失败的会标红，不会存进去。
- 也可以直接填 Open ID、User ID 或 Union ID。Open ID 必须属于**这个 bot 的应用**，别的应用的 Open ID、不在应用通讯录可见范围内的人都会被拒绝。
- 开启时至少要有一个能匹配的对象，否则保存不了。

发消息的人仍然要**有对话权**，替身模式不放宽权限。想让群里所有人都能 @ 替身对象提问，和 [Oncall 模式](/oncall)一起用。

### 哪些消息会触发

- 只认发送者亲手 @ 的文字和富文本消息。转发的卡片、合并转发里带出来的 @ 不算。
- @ 了替身对象，但正文以 `/` 开头（斜杠命令）的，不触发；命令里的 @ 视为命令参数，消息照常按普通路径处理。
- 配了「触发关键词」时，还要求正文包含任意一个关键词，否则不代答，且这条消息不再走任何其他兜底（已有会话、免 @、单人群都不接话），相当于当作没看到（详见下文 `keywords`）。
- 普通群：替身回合进这个群的群会话，回复挂在触发消息下面。
- 话题群：替身回合进该话题自己的会话（没有就新开一个），回复留在原话题里。

### 配置项

Dashboard 里的每一项都对应 [bots.json](/bots-json) 里这个 bot 条目的 `substituteMode`：

```json
{
  "substituteMode": {
    "enabled": true,
    "targets": [
      { "openId": "ou_example", "name": "值班同学" }
    ],
    "keywords": ["独立卡", "oncall"],
    "disclosure": "prefix",
    "replyMode": "thread",
    "chats": [],
    "excludedChats": ["oc_example"],
    "topicGroups": true,
    "topicActiveSessionTrigger": true,
    "disableControlCard": false
  }
}
```

| 字段 | Dashboard 里的名字 | 含义 |
|------|------|------|
| `enabled` | 启用替身触发 | 总开关。关掉时替身对象等配置会保留，下次打开不用重填 |
| `targets` | 替身对象 | 被代答的人或机器人。每项写 `openId` / `userId` / `unionId` 之一，机器人也可以只写 `appId`（见下文）；`name` 是给 AI 看的显示名（可选） |
| `keywords` | 触发关键词（可选） | 字符串数组，留空或省略表示「@ 替身对象即触发」。填写后，同一条消息必须既 @ 替身对象、正文又包含其中任意一个关键词才代答；大小写不敏感的子串匹配，只看本条消息亲手输入的文字和富文本，不含 @ 名称、引用/转发或历史消息，正文解析不出来时按不命中处理。**关键词未命中时整条消息直接丢弃、bot 不接话，不会再落到已有会话、免 @ 或单人群等任何兜底**（直接 @ 机器人本身、或正文以 `/` 开头的斜杠命令除外）。Dashboard 里用换行、逗号或分号分隔 |
| `disclosure` | 披露方式 | `prefix`（默认）：要求 AI 回答时说明自己在替谁回答；`none`：不额外要求说明 |
| `replyMode` | 回复方式 | 只影响普通群。`thread`（默认）：在触发消息下开话题回复；`quote`：引用触发消息回复，不开新话题 |
| `chats` | 生效群聊 | 白名单。留空表示所有群都生效；填了就只在这些群触发 |
| `excludedChats` | 黑名单群聊 | 列出的群里永不触发，群内 `/substitute on` 也打不开。同时出现在白名单和黑名单里的群，以黑名单为准 |
| `topicGroups` | 话题群支持 | 默认开。设为 `false` 后只在普通群生效 |
| `topicActiveSessionTrigger` | 已有活跃会话的话题里也触发 | 默认开。设为 `false` 后，话题里已有本 bot 的会话时，@ 替身对象视为转交给别人，bot 保持安静 |
| `disableControlCard` | 发送 owner 控制卡片 | 普通群的替身会话启动后，默认私信 owner / `allowedUsers` 一张控制卡（打开终端、重启、关闭）。设为 `true` 不发。话题群照常有流式卡片，不另发 |

几点注意：

- 手写 bots.json 时，`targets` 里**只写邮箱匹配不到人**：飞书的 @ 里不带邮箱。邮箱只会被当作备注保留；如果开着替身模式、却没有一个对象带 `openId` / `userId` / `unionId` / `appId`，整段 `substituteMode` 在加载时会被忽略。需要按邮箱填，请在 Dashboard 里保存，让它解析成 Open ID。
- 手动改完执行 `botmux restart` 生效。
- 黑名单群里，@ 替身对象的消息会被直接忽略，不会再走其它免 @ 规则。直接 @ bot 照常回答。

### 按 App ID 配置机器人替身

想让 bot 替另一个机器人回答，在替身对象里选 **App ID**，填 `cli_...` 即可；bots.json 里写成 `{ "appId": "cli_example" }`。不用再填 Open ID、群 ID，也不按显示名匹配。

- 文字和富文本里的 @ 都认。真人发的、有对话权的机器人发的都会触发。
- 生效群聊、黑名单、本群 `/substitute off`、触发关键词、活跃话题这些规则，和按 Open ID 配置的替身一样；被拦下的消息同样不再走其它兜底。机器人发来的消息也按这套规则判断，被拦下时不会触发「其他机器人开新话题自动开工」。
- 飞书推来的事件里只有接收方视角的 Open ID，bot 会再用「获取指定消息」接口读这条消息，换出 App ID。读取失败、读到的版本与事件不一致、或身份对不上时，这条消息不按 App ID 替身处理。
- 机器人发来的替身消息在会话里排队时，轮到它之前会再查一次发送方权限和替身配置；排队期间被撤权、拉黑、关掉替身或改了配置，这条就不再处理。
- 保存时只检查格式（大写会转成小写），不检查应用是否存在、是否已入群，也不会为了查名字额外申请权限。手写 bots.json 时格式不对的 `appId` 会在日志里告警并忽略这一项。

### 单个群临时开关

替身模式默认在所有生效的群里开着。想在某个群临时关掉，在群里 @ bot 发：

```text
@bot /substitute status     # 查看本群是否开启
@bot /substitute off        # 本群关闭
@bot /substitute on         # 本群重新打开
```

- 查看不限人，开关需要**操作权**（owner / `allowedUsers`）。
- 普通群和话题群都能用，私聊不支持。
- 群在黑名单里，或者话题群但 `topicGroups` 关了，命令会直接告诉你本群用不了，不会假装开启成功。

## 关掉「1 人 1 bot 群免 @」

群里只有 1 个人和 1 个 bot 时默认免 @。想让这类群也按 @ 策略走，在对应 bot 的 [bots.json](/bots-json) 条目里配置：

```json
{
  "regularGroupMentionMode": "always",
  "soloGroupMentionBypass": false,
  "chatSoloGroupMentionBypass": {
    "oc_example": true
  }
}
```

| 字段 | 含义 |
|------|------|
| `soloGroupMentionBypass` | bot 级开关。不写或 `true`：保持免 @；`false`：关掉这个例外 |
| `chatSoloGroupMentionBypass` | 按群覆盖。显式 `true` / `false` 优先于 bot 级开关；删掉某个群的条目就恢复继承 |

上面的例子：只有 `oc_example` 这个群保留免 @，其余群都关掉。如果只想关一个群，就保留 bot 默认，在映射里把那个群设成 `false`。

手动改完执行 `botmux restart` 生效。

关掉之后：

- 是否回应由**生效的 @ 策略**决定（群级优先）：`always` 要 @；`topic` 仍可在已接管的话题里免 @ 续聊；`never` / `ambient` 照旧。
- 在 `always` / `topic` 下，没 @ 的顶层文字、图片不会再因为「群里人少」就触发会话。
- 开关对普通群和话题群都生效，不影响私聊；权限检查和「点名让路」照常。

这个开关只关掉「人少」带来的隐式例外。消息监听、免 @ 命令、替身、入群 / 新话题自动开工这些显式配置各自独立。想要**严格只认 @**：把开关设为 `false`，把群的 @ 策略设为 `always`，再检查这个群有没有开别的触发方式。

另外，判断「是不是 1 人 1 bot」用的是群成员人数。消息里 @ 了别的成员时，bot 会重新查一次人数，避免刚拉进新 bot 时旧 bot 抢话。被 @ 的人不在群里（飞书允许 @ 群外的人）、重查后仍是 1 人 1 bot 时，照常免 @。

## 进阶：可信建群服务

如果你的部署接入了可信建群服务，并在 bots.json 里开了 `signedChatDefaults`，由该服务创建的群会默认按 `ambient` 处理。这时的优先级是：群级 `/mention-mode` 设置 → 建群服务声明的 `ambient` → bot 默认。它同样只影响「要不要 @」，不放宽任何权限。

> 相关：回复落到新话题还是当前会话，由 `/reply-mode` 控制，见[斜杠命令](/slash-commands)。
