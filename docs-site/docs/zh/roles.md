# 角色与团队

给机器人设一段「人设」（Role），告诉它在群里是谁、负责什么、说话什么风格。同一个 bot 可以在不同群里扮演不同角色。命令是 `/role`。

本页内容一览：

| 想做什么 | 看哪节 |
|------|------|
| 给 bot 设人设（全局默认 / 某个群单独设） | [设置人设](#设置人设) |
| 控制人设注入频率、私聊回复提问人等群级开关 | [群级开关](#群级开关) |
| 把一套人设一次性应用到新群 | [角色配置集（Profile）](#角色配置集profile) |
| 让别的 bot 知道「谁擅长什么」 | [能力标签](#能力标签) |
| 一个 bot 拥有多个角色、各自独立记忆（进阶） | [角色切换](#角色切换进阶) |

## 设置人设

人设分两级：

- **默认角色**：这个 bot 在**所有群**里的默认人设。
- **本群 Role**：只在**当前群**生效，会覆盖默认角色。

生效顺序永远是：**本群 Role > 默认角色 > 无**。比如同一个 bot，在 A 群当「严格的代码评审」，在 B 群当「耐心的答疑助手」，其它群用默认角色。

### 在群里用命令

在群里 @ 机器人发：

| 命令 | 作用 |
|------|------|
| `/role` | 查看当前生效的人设，并说明来源（本群 / 默认） |
| `/role set <Markdown>` | 设置本群 Role，可以写多行 |
| `/role delete` | 删除本群 Role，回落到默认角色 |
| `/role team` | 查看默认角色 |
| `/role team set <Markdown>` | 设置默认角色（命令名沿用了 `team`，意思就是「默认角色」） |
| `/role team delete` | 删除默认角色 |

示例：

```text
/role set 你是本群的技术顾问。
- 回答先给结论，再给理由
- 涉及线上变更时先提醒风险
```

- 人设用 Markdown 写，会作为一段 `<role>` 注入给 CLI。
- 每段人设最多 32 KB（约 1 万个汉字），超出部分会被截断。
- 改完后，「每轮注入」模式从下一条消息开始生效；「仅首轮注入」模式要等新会话或会话重建（见下方 [群级开关](#群级开关)）。

### 在 Dashboard 里编辑

不想敲命令，可以打开 `botmux dashboard`：

| 要改什么 | 去哪里 |
|------|------|
| 默认角色 | **Bot 配置** 页，每个 bot 的「**默认角色**」区块（和 `/role team set` 是同一份配置；留空保存即删除） |
| 本群 Role | **角色管理** 页 →「按群组」，展开群、选中 bot 编辑 |
| 从某个群跳过去改 | **群组管理** 页，在群里某个 bot 的设置里点「编辑群角色」 |

![Dashboard Bot 配置 — 默认角色编辑器](https://magic-builder.tos-cn-beijing.volces.com/uploads/1780051089378_default-role-shot.png)

在群组管理页「复制为新群」时，可以勾选「同时复制群角色」，把源群里单独设置的本群 Role（连同下面的群级开关）一起带到新群；默认角色本来就会自动继承，不需要复制。

## 群级开关

在 **角色管理** 页选中某个群里的某个 bot，除了编辑人设，还能设置下面几项。它们都按「群 + bot」单独保存，改动即时生效。

| 开关 | 默认 | 说明 |
|------|------|------|
| **注入方式** | 每轮注入 | 「每轮注入」每条消息都带上人设；「仅首轮注入一次」只在会话开始或重建时注入，后面不再重复，适合长人设、省 token。默认值可以在 Bot 配置页的「默认角色」里按 bot 统一改，单个群再覆盖 |
| **优先私聊回复提问人** | 关 | 开启后，答案优先私聊发给提问的人；私聊失败时在原话题公开回复。还可以填一句「群内提示文案」（如「为避免打扰，已经私聊发送」），私聊成功后显示在原话题，留空则不提示 |
| **话题任务回报方式** | 关 | 见下 |

**话题任务回报方式**：这个 bot 在本群用 `botmux dispatch` 给别的 bot 派任务时，对方完成后照常用 `botmux report` 把结果交回给派发方的会话。开启这个开关后，对方还会额外在收到任务的那个话题里用 `botmux send --no-mention` 发一条「完成情况 + 产出位置/摘要」，方便人在群里直接看到结果。它不会 @ 派发方，也不会新开话题。用 `--standby` 只占位、不发任务时，不涉及这一步。

> 项目群里的主控 bot 还会另外收到 Botmux 固定的项目状态协议（用于维护项目进展、置顶项目卡）。它和 Role 并列生效，不受 Role 的注入方式影响。项目群的用法见 [斜杠命令](/slash-commands) 里的 `/project`。

## 角色配置集（Profile）

Profile 是一套**可复用的本群 Role 套装**：给多个 bot 各写一段人设，存成一个名字（比如 `collab-main`），以后在新群里一键应用。

它只是「快捷写入」：应用后就变成普通的本群 Role，不会多出一层人设，也不支持模板继承。

### 命令

| 命令 | 作用 |
|------|------|
| `/role profile list` | 列出所有 profile，并标出当前 bot 有没有自己的条目 |
| `/role profile show <名字>` | 查看当前 bot 在这个 profile 里的人设；加 `--all` 看所有 bot 的 |
| `/role profile set <名字> <Markdown>` | 直接写入当前 bot 的条目 |
| `/role profile save <名字>` | 把当前 bot 正在生效的人设（本群 Role，没有就用默认角色）存进 profile |
| `/role profile delete <名字>` | 删除当前 bot 的条目 |
| `/role profile apply <名字>` | 把当前 bot 的条目写成本群 Role |

`apply` 的几个参数：

- `--preview`：只预览，不写入。
- `--force`：本群已经有 Role 时，默认会拒绝覆盖；加上它才覆盖。
- `--quiet`：成功时不回复消息（批量应用时减少刷屏）。

几点说明：

- 每个 bot 只管自己的那一条，不会改别的 bot 的人设。
- profile 里没有当前 bot 的条目时，`apply` 什么都不写，该 bot 继续用默认角色。
- profile 名字只能用字母、数字、`.`、`_`、`-`，最长 64 个字符。

### 在 Dashboard 里用

**角色管理** 页 → 「Profiles」标签：

1. 在左侧打开或新建一个 profile。
2. 中间能看到每个 bot 有没有条目，选中 bot 编辑它的人设。
3. 在「Apply 到群组」里选目标群和要应用的 bot，先点 **预览 Apply** 看看会不会覆盖已有 Role，确认后点 **Apply Profile**。需要覆盖时勾选「覆盖已有本群 Role」。

### 建群时直接带上

```text
@botA @botB @botC /g --role-profile collab-main 作战室
```

新群建好后，发起建群的 bot 先应用自己的条目，再在新群里发一条 `@botB @botC /role profile apply collab-main --quiet`，让其它 bot 各自应用自己的条目。

## 能力标签

能力标签是一句话的自我介绍，比如「擅长前端和 UI 走查」，帮你和其它 bot 在协作时挑对人。

```text
/role cap set 擅长前端和 UI 走查   # 设置
/role cap                          # 查看
/role cap clear                    # 清除
```

- 标签最多 120 个字符，写一句话就够，完整人设请用 `/role set`。
- 其它 bot 运行 `botmux bots list` 查看群里有哪些机器人时，会看到每个 bot 的标签。
- 小技巧：在标签里写上 `workspace: required` / `optional` / `none`，派任务的 bot 就知道给你派活时是否必须指定仓库或工作目录。

人设 + 能力标签是 [多机器人协作](/multi-bot) 的基础：每个 bot 身份清楚、分工明确，群里 @ 时就不容易混淆。

## 团队：跨机器协作

以前 Dashboard 里有一个「团队」页，现在已经下线。想找**别人机器上的**机器人来协作，需要本机先接入中心平台、并和对方在同一个团队，然后用命令行：

- `botmux bots list --scope team`：列出同团队、已加入团队的机器人。
- `botmux create-group --team <团队> --agent <appId>`：把它们和各自的 owner 一起拉进新群。

完整步骤见 [多机器人协作](/multi-bot) 里的「团队维度」一节。

## 角色切换（进阶）

> ⚠️ 进阶功能：需要先部署「角色库」，目前只支持 Claude Code。部署步骤见仓库里的 [角色系统部署 runbook](https://github.com/deepcoldy/botmux/blob/master/docs/roles/deploy-runbook.md)。下面讲部署好之后怎么用。

上面的 `/role` 是「一个 bot 一套人设」。**角色切换**则让一个 bot 拥有**多个完整角色**，每个角色有自己的人设和**独立记忆**。切到「售后客服」，它就带着售后的人设和只属于售后的经验；切到「产品经理」，又是另一套。

角色**按话题生效**，新话题从默认角色开始。

### 怎么用：直接说话就行

| 你说 | bot 做什么 |
|------|-----------|
| 「切换角色」/「有哪些角色」 | 列出你能用的角色（共享的 + 你自己建的），编号给你选 |
| 「切到售后客服」或回复编号 | 确认后切换，之后这个话题由该角色回答，卡片脚注也会显示角色名 |
| 「新建角色：小红书运营，熟悉我们品牌调性」 | 先起草人设给你确认，然后创建并自动切过去 |
| 「沉淀知识」 | 把这个角色近期的记忆整理成结构化知识，存回角色自身（也可以整理成飞书文档供人审核） |

背后是模型在调用 `botmux role switch <角色目录>`，你不需要自己敲这个命令。

### 需要知道的几点

- **独立记忆**：每个角色一份记忆，跨群、跨话题共用，越用越懂自己的领域。
- **上下文不丢**：切换时 CLI 会重启并续上之前的对话，新角色的人设和记忆在新会话开始时自动加载。
- **私有角色不是安全边界**：「只能看到共享角色和自己建的角色」是角色协议文件（`_role-protocol.md`）里的约定，由模型遵守。daemon 只强制一件事：目标目录必须在角色库 `~/botmux-roles` 里面，不会按发送者做权限隔离。真要隔离，请自行加系统级权限。
- **和 `/cd` 不是一回事**：`/cd <路径>`（见 [斜杠命令](/slash-commands)）是通用的「换工作目录并重启」，可以切到任意目录，需要操作权限；角色切换只能在角色库里切。

> 老命令 `botmux cd` 已改名为 `botmux role switch`。旧命令现在只会报错提示、不会执行切换。维护老部署时，记得把角色库里的 `_role-protocol.md` 改成新命令。
