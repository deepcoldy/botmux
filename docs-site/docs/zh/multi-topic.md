# 多话题协作模式

[多机器人协作](/multi-bot) 的升级版：把一个大任务交给主 bot，它会自动把任务拆成多个子项目、在群里开多条话题、给每条话题派一组 bot 并行干活（常见「一个写、一个 review」），用一张飞书任务清单当共享进度板，最后收齐结果汇总给你。一个普通群就变成一个并行工作台。

## 怎么用

跟主 bot 说一句就行，比如：

> 「用多话题协作模式，把 ×× 拆成几个子项目并行做」
>
> 「你来当编排，协调几个 bot 并行推进这个需求」

接下来主 bot 会自动：

1. 把任务拆成几个子项目，先给你**一版分配方案**（每个子项目派哪些 bot），等你确认；
2. 你点头后，在群里开多条话题、把对应的 bot 拉进去并行开干；
3. 建一张**飞书任务清单**当进度板——你在飞书任务里一眼看到每个子项目的进度；
4. 各组干完后，主 bot 收齐、把结果汇总给你。

你全程只需要：**说需求 → 确认分配 → 看进度 / 收结果**。开话题、分工协作、互相回报这些都在 bot 之间自动完成，你不用操心。

## 前置条件

想让哪些 bot 参与协作，先把它们拉进这个群、确保能被 @ 到（见 [多机器人协作](/multi-bot)）。其余的——在哪个仓库干活、怎么开话题派活——主 bot 都会自动处理，你不用预先配置（不需要先开 OnCall 之类的）。

## 派发中的用户身份

启用 `triggerUserAuth` 后，`botmux dispatch --bot-app` 通过当前真人回合建立消息绑定的身份委托；接收方仍需校验目标应用的用户映射、群成员资格和工具授权。普通 Bot 消息不会自动获得真人权限。

TRAE 会话以结构化日志中的 `task_complete`（成功或失败）或 `turn_aborted` 结束已开始的回合。工具执行期间的终端空闲画面不会撤销当前用户身份。若来源回合已失效，受保护派发会返回 `dispatch_turn_unproven`，不会把缺少身份的任务当作成功派出；不能用会话 Owner 或历史发送者替代当前发起人。

## 任务树卡片（默认关闭）

编排会话可以在自己的话题里收到一张**任务树卡片**：首次 `botmux dispatch` 派单后自动发出，之后子话题被接手、回报（`botmux report --status …`）、完成、失败时原地更新同一张卡片，每个子任务显示状态（在跑 / 等人 / 已完成 / 失败 / 已派发 / 已关闭）、最后一句进展和「打开话题」链接；也可用 `botmux dispatch tree` 手动刷新，用 `--kind review|task`、`--task-id`、`--task-url` 标注审查类型和需求。

该功能**默认关闭**（属于会额外发一条消息的能力）。开启：Dashboard「全局设置 → 多话题协作 → 派发子任务时发送任务树卡片」；需先启用「多话题协作」。关闭时不发卡片、不写卡片记录，派发登记也不新增相关字段，dispatch 的行为与未开启时完全一致；`botmux dispatch tree` 会提示开关位置并以退出码 0 返回。生效时间：daemon 侧发卡/改卡约 2 秒读缓存内生效、无需重启；沙箱/文件隔离会话内的 CLI 读不到全局配置、靠 daemon 在启动会话时注入的环境变量，所以已运行会话内的派发时间戳（`attemptAt`）判定自下一个新会话生效。部署环境也可设 `BOTMUX_DISPATCH_TASK_TREE_CARD_ENABLED=true`，环境变量优先。

## 关闭功能

多话题协作默认开启。若当前机器不需要该功能，可在 Dashboard 的「设置 → 多话题协作」中关闭「启用多话题协作」。设置从下一个会话开始生效，无需重启。

关闭后：

- Agent 不再看到 `botmux-orchestrate` Skill。
- `botmux dispatch` 不能新建子项目话题。
- `botmux dispatch --into <话题根消息 ID>` 仍可向已有话题追加内容，不影响普通 Bot 接力。

部署环境也可设置 `BOTMUX_MULTI_TOPIC_ENABLED=false`。环境变量优先于 Dashboard 中保存的配置。
