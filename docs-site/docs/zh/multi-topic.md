# 多话题协作模式

<video src="img/video-v4-multibot.mp4" controls preload="metadata" style="width:100%;border-radius:8px"></video>

把一个大任务交给主 bot，它会：

- 把任务拆成几个子项目；
- 在群里为每个子项目开一条**子话题**，派一组 bot 进去并行干活（常见搭配：一个写代码、一个 review）；
- 用一张**飞书任务清单**当大家共享的进度板；
- 等各组干完，把结果收齐、汇总给你。

一个普通群就变成了并行工作台。它建立在 [多机器人协作](/multi-bot) 之上。

![多话题协作 · 飞书任务面板当共享进度板](https://magic-builder.tos-cn-beijing.volces.com/uploads/1780419243796_multitopic-board.png)

## 什么时候用它

| 你的需求 | 用什么 |
|---|---|
| 一个长期项目，要**多个 bot 分工**、各自在独立话题里推进，主 bot 持续跟进并最终验收 | 多话题协作（本页） |
| 只是把下一步或一个专项交给另一个 bot | 在当前话题里直接 @ 它接力（见 [多机器人协作](/multi-bot)），**不会**新开话题 |
| 一个有边界的多步任务，跑完就结束、产出一份交付物（如「调研后出报告」） | [Workflow](/workflow) |
| 想在群里置顶一张卡，集中显示目标、待办、阻塞和各子任务状态 | [项目进度卡](/project-card)（可以和本页叠加用） |

## 怎么用

跟主 bot 说一句就行，比如：

> 「用多话题协作模式，把 ×× 拆成几个子项目并行做」
>
> 「你来当编排，协调几个 bot 并行推进这个需求」

接下来主 bot 会按这个顺序走：

```
你提需求
  │
  ▼
① 主 bot 拆子项目，发一版「子项目 ↔ bot」分配方案 ──► 等你确认（可改、可手动指派）
  │
  ▼
② 建飞书任务清单，每个子项目一条任务，并把你加为成员 ──► 你在「飞书任务」里就能看到
  │
  ▼
③ 每个子项目开一条子话题，把对应 bot 拉进去开干
  │
  ▼
④ 子 bot 干完：在任务清单里标完成，再把回报发回主 bot 的话题
  │
  ▼
⑤ 主 bot 收齐结果，推进下一批（有依赖的话），最后给你一份总汇总
```

你全程只需要三件事：**说需求 → 确认分配 → 看进度 / 收结果**。开话题、分工、互相回报都在 bot 之间自动完成。没经过你确认，主 bot 不会建进度板，也不会派活。

## 开始前准备

- **把要参与的 bot 拉进这个群**，并确保它们能被 @ 到（见 [多机器人协作](/multi-bot)）。主 bot 派活前会先查一遍群里有哪些可协作的 bot。
- 其余的不用预先配置：在哪个仓库干活，主 bot 派活时会替每个子 bot 定好工作目录，子 bot 起会话后直接进目录，不会弹「选仓库」卡。如果某个子 bot 已经配了默认工作目录，或它自己在这个群绑了 [OnCall](/oncall)，主 bot 可以不替它指定，它直接用自己的目录。

## 协作过程中

| 想做什么 | 怎么做 |
|---|---|
| 看整体进度 | 打开飞书任务里的那张任务清单；或打开下面的「任务树卡片」 |
| 看某个子项目的细节 | 点进它的子话题，和平常一样看 bot 干活 |
| 调整计划、改派、追问进展 | 在**主 bot 的话题**里跟它说，它会把话转进对应子话题 |

小提示：子 bot 的会话只在自己的子话题里。主 bot 跟子 bot 说话也会进对应子话题，不会在主群里 @ 它（在主群 @ 只会另起一个没有上下文的新会话）。

## 任务树卡片（可选，默认关闭）

开启后，主 bot 第一次派活时，会在它自己的话题里发一张**任务树卡片**：每个子话题占一行，显示状态、最后一句进展和「打开话题」链接。之后子话题被接手、回报、完成或失败时，这张卡会**原地更新**，不会刷屏。

卡片上的状态：

| 状态 | 含义 |
|---|---|
| 🔵 在跑 | 子 bot 正在干活 |
| 🟠 等人 | 卡住了，需要有人处理 |
| 🟢 已完成 | 子项目完成 |
| 🔴 失败 | 子项目失败，或派发没成功 / 子 bot 迟迟没接单 |
| ⚪ 已派发 | 已派出，还没被接手 |
| ⚫ 已关闭 | 子话题已关闭 |

review 类子话题会带「［审查］」标记。卡片头部还可以显示需求 ID 和需求链接。

**怎么开**：Dashboard「全局设置 → 通用设置 → 多话题协作」，打开「派发子任务时发送任务树卡片」。前提是「启用多话题协作」已打开。

- 改完约 2 秒生效，不用重启。
- 运行在沙箱里的会话，要从下一个新会话开始才完全按新设置走。
- 关着时，不发卡片，派活行为和没有这个功能时完全一样。
- 部署环境也可以设环境变量 `BOTMUX_DISPATCH_TASK_TREE_CARD_ENABLED=true`，环境变量优先于 Dashboard 设置。

## 关闭多话题协作

多话题协作**默认开启**。不需要的话，在 Dashboard「全局设置 → 通用设置 → 多话题协作」关掉「启用多话题协作」。从下一个会话开始生效，不用重启。

关掉以后：

- bot 不会再拿到编排技能（`botmux-orchestrate`），也就不会主动开子话题；
- 新开子项目话题会被拒绝；
- 往**已有**话题追加内容仍然可用，普通的 bot 接力不受影响。

部署环境也可以设 `BOTMUX_MULTI_TOPIC_ENABLED=false`，环境变量优先于 Dashboard 设置。

## 进阶：命令参考

这些命令主要由 bot 自己调用，一般不用你手动敲。想了解或排查时可以参考：

| 命令 | 作用 |
|---|---|
| `botmux dispatch --title "<标题>" --bot-app <应用ID[:角色]> --brief-file <文件>` | 新开一条子项目话题，把 bot 派进去；`--bot-app` 可重复写多个 |
| `botmux dispatch ... --repo <目录>` | 给子 bot 预设工作目录 |
| `botmux dispatch ... --repo <目录> --standby` | 只把 bot 拉起来、定好目录待命，不派具体任务 |
| `botmux dispatch --into <话题根消息ID> --bot-app <应用ID> --brief "<内容>"` | 往已有子话题追加一条（追问、补任务、激活待命的 bot） |
| `botmux dispatch ... --kind review` | 在任务树里把这个子话题标成「审查」（默认是任务） |
| `botmux dispatch ... --task-id <需求ID> --task-url <https 链接>` | 把需求 ID / 链接显示在任务树卡片头部 |
| `botmux dispatch ... --model <模型> --reasoning-effort <强度>` | 为新子话题指定模型和推理强度（只支持单个 bot 的新话题，且目标 bot 的 CLI 要支持指定模型） |
| `botmux dispatch tree` | 手动刷新任务树卡片，并打印文字版；功能没开时只提示开关位置 |
| `botmux report --status <状态> "<进展>"` | 子 bot 把进展发回主 bot；状态可选 `pending` `in_progress` `blocked` `completed` `failed` |

完整参数用 `botmux dispatch --help` 查看。

## 进阶：派活时用谁的身份

如果 bot 开了按人授权（`triggerUserAuth`，即 lark-cli 等工具按「本轮发消息的人」的个人授权执行），主 bot 用 `--bot-app` 派活时，会把**当前这一轮发起人**的身份一并交给子 bot。几条规则：

- 子 bot 那边仍会自己核对：这个人在它的应用下是否对得上、是否在群里、是否授权过对应工具。
- 只有真人发起的当前这一轮才能带身份。如果这一轮已经结束，需要带身份的派活会直接被拒绝（错误码 `dispatch_turn_unproven`），不会悄悄当成「没身份」派出去。
- 不会用会话 Owner 或之前发过消息的人顶替当前发起人。普通的 bot 消息也不会因此获得真人权限。
- 想让子 bot 帮人建定时任务，需要额外加 `--delegate schedule:create`，并且宿主策略允许，详见 [定时任务](/schedule)。
