# 语音总结与语音识别

botmux 的语音功能有两个方向，可以只开一个，也可以都开：

| 想做什么 | 功能 | 配置命令 |
|---|---|---|
| 把 AI 的长回复变成一段**语音**听 | 语音总结（TTS，文字转语音） | `botmux voice` |
| 直接给机器人**发语音**，让它当文字指令处理 | 语音识别（ASR，语音转文字） | `botmux voice asr` |

两者都是可选的高级功能，默认关闭，配好后 `botmux restart` 生效。

## 语音总结：一键把回复变成语音

<video src={video_v6_oncall_voice} controls preload="metadata" style={{width:'100%',borderRadius:'8px'}}></video>

配好语音引擎后，机器人发的回复卡片底部会多一个「🔊 语音总结」按钮。点一下：

1. 机器人把它**上一条回复**压成不超过 5 句的口语，只讲结论，去掉代码、命令、路径、链接这类不适合朗读的内容；
2. 合成一条飞书语音消息，发回当前会话。

你听到的是「讲人话」的总结，而不是把原文照念一遍。

使用时要知道的几点：

- **想听才点**：不会自动给每条回复配语音。
- **每张卡片只生成一次**：重复点或多人一起点，也只会出一条语音，不会刷屏。
- **要等会话空闲**：AI 还在干活时点，会提示「会话当前还在执行中」，等它停下再点；会话已离线时也无法生成。
- **有权限门**：只有对这个机器人有使用权限的成员能点，其他人会看到「没有该机器人的使用权限」的提示。
- **没配引擎就没有按钮**。AI 用 `--top-level` 发到群顶层的广播消息也不带这个按钮。

### 第 1 步：选一个语音引擎

运行 `botmux voice`，按提示选引擎、粘贴凭证。配置写进全局 `~/.botmux/config.json` 的 `voice` 块。这个命令特意和 `botmux setup` 分开。

| 引擎 | 适合谁 | 需要准备 | 默认音色 |
|---|---|---|---|
| `[1]` SAMI | 字节内部用户 | appkey、AccessKey、SecretKey | `zh_female_cancan_mars_bigtts`（灿灿） |
| `[2]` OpenAI 兼容 | OpenAI 官方，或自建 TTS 服务 | baseUrl、model，apiKey 可选 | `alloy` |
| `[3]` MiniMax | 有 MiniMax 开放平台 API key | API key、接入区域 | `female-shaonv` |
| `[4]` 火山引擎 / 豆包 V3 | 有火山引擎语音账户 | 模式（standard / agent-plan）+ 对应 API key | `zh_female_vv_uranus_bigtts` |

配置过程中还会问音色和语速倍率，直接回车就用默认值。

#### SAMI（字节内部）

1. 在公司**语音能力平台**申请「**语音合成（大模型）**」能力。botmux 只做合成，不需要申请语音识别。
2. 拿到 **appkey**、**AccessKey**、**SecretKey** 三项。如果提示 Namespace 未开通或无路由，走内部 Oncall 找语音团队开通。
3. 运行 `botmux voice`，选 `[1]`，依次粘贴 accessKey / secretKey / appkey。

服务地址已内置，一般不用填（配置时会问要不要自定义端点，回车跳过即可）。SecretKey 只在本机用来签名换临时 token，不会发出去。

#### OpenAI 兼容

可以接 OpenAI 官方，也可以接自建服务（如 Kokoro-FastAPI、openedai-speech）。要准备三项：

- **baseUrl**：服务地址。OpenAI 官方是 `https://api.openai.com/v1`，自建填自己的，如 `http://127.0.0.1:8880/v1`。
- **model**：模型名。OpenAI 是 `tts-1`，自建按服务文档填（如 `kokoro`）。
- **apiKey**：服务密钥。自建服务没有鉴权就留空。

运行 `botmux voice`，选 `[2]`，按提示填写。音色默认 `alloy`，自建服务按它支持的音色填。

#### MiniMax（海螺语音）

1. 在 [MiniMax 开放平台](https://platform.minimaxi.com) 开通语音合成（T2A），拿到 **API key**。
2. 运行 `botmux voice`，选 `[3]`，粘贴 API key，再选接入区域：
   - `[1]` 国际 `api.minimax.io`（默认）
   - `[2]` 国内 `api.minimaxi.com`

**key 和区域要对得上**，国内账号选国际区域（或反过来）会报鉴权失败。模型默认 `speech-2.8-hd`。默认音色在你的账号下不可用时，换成 MiniMax 控制台里列出的系统音色 id 即可。

#### 火山引擎 / 豆包 V3

1. 运行 `botmux voice`，选 `[4]`。
2. 选模式（必选，没有默认值）：
   - `standard`：普通按量账户
   - `agent-plan`：方舟 Agent Plan 专用账户
3. 粘贴**这个模式专用**的 API key。

语速默认 `1`，实际请求会限制在 `0.5` 到 `2` 之间。key 继承、端点等细节见文末「火山引擎进阶说明」。

### 第 2 步：装好 opus 编码器

飞书语音消息是 opus 格式，合成后要用系统的 **opus-tools**（提供 `opusenc`）转码。`botmux voice` 保存配置时会自动检测，没装会问你要不要现在装。也可以手动装：

```bash
# Debian / Ubuntu
sudo apt-get install -y opus-tools
# macOS
brew install opus-tools
```

### 第 3 步：重启生效

```bash
botmux restart
```

之后回复卡片底部就会出现「🔊 语音总结」按钮。

## 语音识别：发语音给机器人

开启后，给机器人发一条飞书语音消息（群里、话题里都行），botmux 会：

1. 先回一条「🎤 正在转写语音…」；
2. 下载语音，调用你配置的识别服务转成文字；
3. 删掉占位消息，把文字带上「🎤 语音转写：」前缀交给 AI，跟你打字发的指令一样处理。新话题和话题里的续聊都支持。

转写失败（下载失败、服务报错、超时、结果为空）时，机器人会直接回复具体原因，这条语音不会交给 AI，也不会建出空会话。

没配语音识别时发语音，机器人会回复「未配置语音识别」的提示，同样不会交给 AI。

### 配置

语音识别走 OpenAI 兼容的 `/audio/transcriptions` 接口（Whisper API 格式），可以接 OpenAI 官方，也可以接自建的 whisper.cpp server、faster-whisper 等。

```bash
botmux voice asr      # 交互式：填 baseUrl / apiKey / model，可选语言提示
botmux restart        # 生效
```

| 项 | 说明 |
|---|---|
| baseUrl | 必填，如 `https://api.openai.com/v1` |
| model | 必填，如 `whisper-1` |
| apiKey | 可选，自建服务没有鉴权就留空 |
| 语言提示 | 可选，如 `zh`，会传给识别服务 |

语音识别和语音总结互相独立：只配识别、不配语音引擎也可以。

## 管理命令

```bash
botmux voice              # 配置语音总结（交互式）
botmux voice status       # 查看语音总结配置（凭证自动打码）
botmux voice disable      # 删除整个 voice 配置，按钮随之消失

botmux voice asr          # 配置语音识别（交互式）
botmux voice asr status   # 查看语音识别配置
botmux voice asr disable  # 只关闭语音识别，保留其它配置
```

注意 `botmux voice disable` 会把全局 `voice` 块整个删掉，语音识别配置也一起没了。只想关识别，用 `botmux voice asr disable`。反过来，用 `botmux voice` 重新配置语音引擎时，已有的语音识别配置会保留。

改完都要 `botmux restart` 才生效。

## 配置文件参考

也可以直接编辑 `~/.botmux/config.json` 的 `voice` 块：

```jsonc
// SAMI（字节内部）
{
  "voice": {
    "engine": "sami",
    "speaker": "zh_female_cancan_mars_bigtts",   // 可选，默认灿灿
    "sami": { "accessKey": "...", "secretKey": "...", "appkey": "..." }
  }
}

// OpenAI 兼容
{
  "voice": {
    "engine": "openai",
    "speaker": "alloy",                            // 可选
    "openai": { "baseUrl": "https://api.openai.com/v1", "apiKey": "...", "model": "tts-1" }
  }
}

// MiniMax（region："cn" 国内 / "global" 国际，默认国际）
{
  "voice": {
    "engine": "minimax",
    "speaker": "female-shaonv",                   // 可选
    "minimax": { "apiKey": "...", "region": "cn", "model": "speech-2.8-hd" }
  }
}

// 火山引擎 / 豆包 V3（mode 必填："standard" 或 "agent-plan"）
{
  "voice": {
    "engine": "volcengine",
    "volcengine": { "mode": "standard", "apiKey": "<STANDARD_API_KEY>" },
    "speaker": "zh_female_vv_uranus_bigtts",      // 可选
    "rate": 1                                     // 可选
  }
}

// 语音识别：可以和上面任意一种放在同一个 voice 块里
{
  "voice": {
    "asr": {
      "enabled": true,                            // 必须为 true 才生效
      "baseUrl": "https://api.openai.com/v1",
      "apiKey": "...",
      "model": "whisper-1",
      "language": "zh",                           // 可选
      "timeoutMs": 120000                         // 可选，转写超时，默认 120 秒
    }
  }
}
```

通用字段：

| 字段 | 说明 |
|---|---|
| `engine` | `sami` / `openai` / `minimax` / `volcengine` |
| `speaker` | 音色 id，不填用该引擎的默认音色 |
| `rate` | 语速倍率，`1` 为正常速度。各引擎会限制在自己支持的范围内（SAMI、MiniMax、火山引擎为 0.5–2，OpenAI 兼容为 0.25–4） |

### 给某个机器人单独配置

在 `bots.json` 某个机器人对象里放同样结构的 `voice` 块，它会**逐字段**盖在全局配置之上。多个机器人可以共用一套全局配置，也可以各配各的，或只改音色、语速。语音识别的 `asr` 也一样可以按机器人覆盖，但机器人自己的 `asr` 块里要写上 `"enabled": true`，否则会把这个机器人的语音识别关掉。

例如让某个机器人改用火山引擎 Agent Plan 账户：

```json
{
  "voice": {
    "engine": "volcengine",
    "volcengine": {
      "mode": "agent-plan",
      "apiKey": "<AGENT_PLAN_API_KEY>"
    }
  }
}
```

## 火山引擎进阶说明

- **`engine` 和 `mode` 都要写明**。缺少或写错 mode，配置就当作不可用（按钮不出现），不会悄悄改走别的计费端点。
- 两种模式固定走 `openspeech.bytedance.com`、资源 `seed-tts-2.0`：`standard` 用 `/api/v3/tts/unidirectional`，`agent-plan` 用 `/api/v3/plan/tts/unidirectional`。不要填聊天服务的地址或旧版 app ID。
- 示例里的 `<...>` 占位符要换成真实 key，botmux 不会去读同名环境变量。
- **按机器人覆盖时的 key 继承**：
  - 和全局是同一个 mode：可以不写 key，直接继承；也可以只覆盖 `speaker` 或 `rate`。
  - 换了 mode：必须同时写新 key，不会继承另一个模式的 key。
  - 写 `"volcengine": null` 或空 key：不继承全局账户。
- `botmux voice status` 只显示 key 是否已设置，不显示内容。
- 合成是等整段音频返回后再发，不是边合成边播放。默认 60 秒超时。请求失败不重试、不跟随重定向、不切换端点；返回数据不完整或超出大小限制时直接报错，不会发出半截语音。计费以服务商为准。
