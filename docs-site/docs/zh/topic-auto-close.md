# 话题资源自动回收

开启后，删除或撤回话题根消息会自动结束对应的 Botmux 任务，释放 worker 和会话绑定。会话记录、工作目录和 Git worktree 保留，不会因为清理资源而删除代码。

这个功能按机器人配置，默认关闭。Dashboard → Bot 配置 → 回复投递 → **话题资源自动回收**，或在飞书里发送：

```sh
/botconfig set topicAutoClose on
```

关闭自动回收：

```sh
/botconfig set topicAutoClose off
```

也可在对应机器人的 `bots.json` 配置 `"topicAutoClose": true`。Dashboard 和命令保存后立即生效，无需重启。

## 回收时机

| 操作或状态 | 行为 |
| --- | --- |
| 撤回话题根消息 | 收到飞书撤回事件后立即进入正常会话关闭流程，正在运行的任务也会停止 |
| 删除根消息，或漏收撤回事件 | 启动时及每分钟巡检根消息；确认已删除后回收 |
| 撤回普通回复 | 保留话题会话 |
| 查询超时、权限不足或状态不明确 | 保留 worker，下次巡检重试 |
| 飞书右键「关闭当前话题」 | 暂无可靠的公开关闭事件或状态接口，不能自动检测；请先用 `/close` 或卡片「关闭会话」结束任务 |

每分钟是巡检频率，不是回收时间保证；会话较多、接口限流或 worker 退出较慢时会延迟。已撤回的话题内不会额外发布关闭消息。Dashboard 可查看会话关闭状态，daemon 日志中的 `[topic-gone]` 记录根消息和关闭结果；关闭被拒绝或留下残留会明确记录。

## 支持边界

- 仅支持常规单副本运行；durable primary 多副本模式保留原有生命周期保护，不执行这项回收。
- 只处理本机器人绑定到该根消息的线程会话，不处理群级会话、其它话题或其它机器人的 worker。
- 撤回事件依赖应用发布生效的 `im.message.recalled_v1` 订阅；巡检依赖机器人读取根消息的权限。查询失败不会当作删除。
- 关闭开关会停止新增的事件回收和巡检回收；已经开始的正常会话关闭不会撤销。原有 `/close` 和发送失败时的关闭规则仍生效。

[原话题不可用策略](/topic-unavailable-policy) 控制是否停止发送或改发其它位置；本开关控制是否释放资源，两者独立。若希望删除话题后停止任务且不向其它位置发送，可同时启用自动回收和 `topicUnavailablePolicy: "stop"`。
