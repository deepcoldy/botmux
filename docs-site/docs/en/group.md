# Create a Session Group in One Step

<video src="../img/video-v4-multibot-en.mp4" controls preload="metadata" style="width:100%;border-radius:8px"></video>

Want a clean group dedicated to one project or task? Send `/group <group name>` (short form `/g`). The bot will:

1. Create a new Lark group and add you to it;
2. Transfer group ownership to you;
3. Reply with a card containing the join link.

Open the group and start talking to the bot. **The whole group is one independent CLI session** (a session is one running AI coding CLI process, such as Claude Code or Codex).

```bash
/g card race-condition bug
```

The reply looks roughly like:

```text
✅ Created group "card race-condition bug"
👉 <join link>

Just start chatting in the new group — the whole group is one CLI session.
```

> Creating the group **does not start a session**. The session starts when you send your first message in the new group.

botmux has two kinds of "session group". This page covers both:

| | Groups created by `/g` | DM dedicated groups |
| --- | --- | --- |
| How they appear | You send `/g` in any chat | Once enabled, every new DM to the bot creates its own group |
| Good for | Opening a workspace for a project / task by hand, optionally with several bots | Giving each DM question its own group so it is easy to look back on |
| See | "Create a group with `/g`" below | "DM dedicated groups" below |

## Create a group with `/g`

### Group name and avatar

- **With a name**: your name is used and never changed afterwards.
- **Without a name** (just `/g`): the group starts with the placeholder "New session MM/DD HH:mm". After your first substantive message in it, the bot summarizes a title of up to 12 characters and renames the group.
- **Avatar**: by default, the botmux logo on a gradient background (one of ten palettes, fixed per group). Add `--avatar name` for a text avatar showing the group name, or `--avatar off` to keep Lark's default.

![Group-name text avatar example](/img/group-name-avatar.png)
*A group-name text avatar generated by `--avatar name`*

About automatic renaming:

- Slash commands, messages that only contain images/attachments, and bot messages are not used for naming.
- If you rename the group yourself first, your name wins.
- In a multi-bot group, only the bot that created the group names it.
- If naming fails, the placeholder stays and naming is retried on your next message (the two retries wait at least 30 seconds and 2 minutes), up to three rounds.
- AI naming runs the CLI once on the host, so it only works when: the CLI is Claude Code, Codex, TRAE CLI (traex), OpenCode, Antigravity, Grok, Pi or oh-my-pi; the bot has no file sandbox; the host has no device-credential isolation; no custom launch mode is used; and Codex does not use private login or an instance pool. Otherwise the placeholder stays.

### Bring several bots along

@-mention bots in the command and they are **all added to the new group**. The first @-mentioned bot creates it:

```bash
@Claude @Codex /g review group authorization
```

The reply lists "🤖 Bots in the group: Claude, Codex". In the group, @ whichever bot should do the work.

If you don't want to @ every time, use `--agents` with names or app IDs. The bots don't have to be in the current chat, but they must be configured in this machine's `bots.json` with a Lark connection:

```bash
/g Project work --agents Review,Build,Check
```

Names are case-insensitive. Unknown or duplicate names fail before the group is created; use app IDs for duplicates.

> If you have set up a [decision-board steward](/en/decision-board) on this machine with "Add the steward to new chats" enabled, and the steward's owner is in the new group, the steward is added too (it stays silent and opens no session). Groups with only you and one bot don't get it by default.

### All options

| Option | Effect |
| --- | --- |
| `--agents A,B` | Also invite these bots (display names or app IDs, comma-separated); replaces the default list |
| `--no-agents` | Ignore the default invite list |
| `--tag <name>` | Put the new group into a message group in your Lark sidebar (up to 60 characters) |
| `--no-tag` | Ignore the default tag |
| `--avatar logo\|name\|off` | Avatar: gradient logo (default) / group-name text / Lark default |
| `--role-profile <id>` | Apply a [role profile](/en/roles) to the bots in the group after creation |
| `--` | End of options: everything after it is part of the group name, handy when the name itself contains text like `--tag` |

```bash
/g Project work --agents Review,Build --tag Projects --avatar name
/g Project work --tag "Project work"
/g --avatar off
```

Notes:

- Values can be written as `--tag=Projects` or `--tag Projects`; quote values with spaces.
- Missing values, invalid values and repeated options fail before the group is created, so you never get a half-wrong group.
- Unknown `--xxx` words are not errors; they stay in the group name as-is.
- `--tag` is a **message group in your personal sidebar**, not a tenant-wide chat tag. The first time, authorize it: send `/login tags` in a chat with that bot and confirm the link. Without authorization the group is still created and the reply tells you what is missing.
- Failures to invite bots, set the tag or set the avatar are reported separately in the reply; the created group is kept.

### Apply a role profile

If you keep reusable collaboration personas in a [role profile](/en/roles), add `--role-profile` when creating the group:

```bash
@Claude @Codex /g --role-profile collab-main review group authorization
```

After the group is created, the creator bot applies its own entry first, then posts `@Codex /role profile apply collab-main --quiet` in the new group so each other bot applies its own. A bot without an entry in the profile is fine; it keeps its default role.

### Set defaults for a bot

If your team always uses the same set of bots and the same tag, give the bot defaults so a bare `/g` is enough. In that bot's `bots.json` entry:

```json
{
  "groupCreation": {
    "agents": ["cli_review_app", "cli_build_app"],
    "tag": "Projects",
    "avatar": "name"
  }
}
```

You can also send `/botconfig set groupCreation <JSON>` in Lark, and `/botconfig unset groupCreation` to reset.

- Options in the command override the defaults.
- With a default list, @-mentioning just one of those bots with `/g` still brings in the whole team (deduplicated).
- `--no-agents`, `--no-tag` and `--avatar off` only drop defaults; they never remove bots you explicitly @-mentioned.
- Without `groupCreation` and without options, only the current bot and the bots you @-mentioned join.

## Create a group in the Dashboard

Prefer not to type commands? Open the **Group Management** page in `botmux dashboard` and click "New Chat":

- Check the bots to add (the Dashboard picks an online bot as the creator);
- Enter a group name;
- Optionally set "Bind Directory": new topics start the CLI there directly, without the repo picker;
- Optionally choose a Lark tag (sidebar message group).

For an existing group, click "**Duplicate**": the source group's bots and bound directory are preselected, and you can also copy the per-group roles.

![Duplicate a group in the Dashboard](/img/groups-clone-chat.png)
*"Duplicate" (the screenshot shows the Chinese UI): bots and bound directory are preselected; per-group roles can be copied too*

Click "Manage" on a group to open its details. The "Leave / Disband" tab lets selected bots leave the group, or disbands it. Disbanding only succeeds when a bot in the group is the owner; otherwise have the bots leave instead.

![Leave and disband in the Dashboard](/img/groups-manage-danger.png)
*The "Leave / Disband" tab in group details (Chinese UI shown)*

The top of the Group Management page switches between "Groups / Session chats"; session chats are sorted by recent activity by default, or by creation time. See [Dashboard Control Panel](/en/dashboard) for more.

## DM dedicated groups

Once enabled, **every new message** you send the bot in a DM creates a group containing just you and that bot to host the conversation, and the DM gets a receipt with the group link.

### Turn it on

Either:

- Dashboard → **Bot Config** → Sessions → Session mode → for DMs choose "**A dedicated group per message**";
- or send `/botconfig set p2pMode group` in Lark (`/botconfig unset p2pMode` goes back to the default "Continuous chat").

After `/close`, the group stays. A new message in it starts a fresh session; use `/resume` to continue the previous one.

### How the group is named

Once DMs are set to "A dedicated group per message", a **Dedicated group naming** option appears below it. Choose there:

| Option | Effect |
| --- | --- |
| AI summary (default) | Use a truncated first message as a placeholder, then generate a short title and rename |
| Reuse Agent session title | Use the title the CLI gives the session, with no extra model call; keep the placeholder until it's ready |
| Truncate first message | Use the truncated first message as the name and never rename |

Or in that bot's `bots.json`:

```json
{
  "sessionGroup": {
    "naming": { "mode": "session-title", "maxLen": 12 }
  }
}
```

`mode` is `ai-summary` / `session-title` / `truncate`; `maxLen` is the maximum title length (default 12).

Notes:

- The group is named automatically once; later title changes are not followed, and a name you set by hand is never overwritten.
- "Reuse Agent session title" accepts Codex's own session titles and titles published through botmux renames (including Agent renames and renames you make in the Dashboard or inside a session).
- For AI summaries, Codex uses an isolated lightweight call: low reasoning, none of your hooks, plugins, MCP servers or project instructions, only the login credentials and model gateway settings. Enter a lightweight model your account can use in "**Summary model (Codex)**" (`naming.model` in bots.json), or leave it blank to use the bot's model. This only affects group naming, not conversations.

### Change the tag on close

By default, dedicated groups go into a message group in your sidebar (such as "XX sessions"). To move closed sessions into another message group automatically (for example "Closed"), set **Tag after closing** under Dashboard "Bot Config → Sessions → Session mode → Direct messages" (shown once DMs are set to "A dedicated group per message"). Leave it empty to disable.

Equivalent `bots.json`:

```json
{
  "p2pMode": "group",
  "sessionGroup": {
    "tag": {
      "mode": "feed-group",
      "name": "Active",
      "closedName": "Closed"
    }
  }
}
```

Rules:

- The move only happens after a **successful** `/close` (or the close-card button). `/stop`, failed closes, crashes and background cleanup never trigger it.
- The group is added to the new message group first, then removed from the old one. A missing message group is created; one with the same name is reused. The group and its history are untouched.
- Only personal message groups (`feed-group`) are supported, using the group creator's authorization; send `/login tags` if it's missing.
- The move runs in the background; failures are reported separately.
- Resuming a session does not move the group back. Clearing "Tag after closing" turns the feature off without bulk-migrating existing groups.

### Disband a dedicated group: `/dismiss`

Want to delete the whole group? Send `/dismiss` at the top level of the dedicated group. The bot replies with a confirmation card listing:

1. The sessions in this group that will be closed (including other local bots' sessions in this group);
2. Disbanding this Lark group (it disappears for all members; cannot be undone);
3. Removing the session-group record (resuming these sessions later will not recreate the group).

Click "**Disband**" to proceed. On success the group disappears and you get the result as a private card. The card also lists the worktrees those sessions used, with a one-click cleanup (equivalent to `git worktree remove --force`: uncommitted changes are lost, branches and committed work stay). If you don't click it, they are kept.

Limits and notes:

- Only the person who created the group, with bot operator permission, can run it.
- The bot must own the group, or be its creator with the `im:chat:operate_as_owner` permission.
- Only works at the top level of a DM dedicated group created by this bot; groups created by `/g`, ordinary groups, DMs and subtopics are not supported.
- It stops without disbanding, and explains why in the group, when: the group has a shared session attached via `/adopt` (run `/detach` first), another local bot is offline, a session couldn't be closed safely, or a new session appeared during confirmation.
- If disbanding fails, sessions that were closed stay closed; send `/dismiss` again to retry.
- Code and worktrees are not deleted by default. To end the session but keep the group, use `/close`.
