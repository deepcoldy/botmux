# 可配置反馈卡与动作扩展

状态：主要运行链路已实现，本轮已修复普通群/代理交付及状态恢复阻断。仍保留 CI 与原生客户端验证门槛；未部署。

## 本次基础变更

- `feedbackPresentation` 提供 bot 默认、群规则和具体问题规则。
- 具体问题覆盖群规则；数组整体替换；同 selector 或 id 重复时报错。
- `rounds` 必须是升序、无重复的正整数；未配置默认关闭。
- 现有反馈按钮定义不复制到展示配置，后续 renderer 必须使用原 delivery 的反馈策略。
- 配置写入和重载共用规范化；直接写入无效展示规则也会拒绝。
- 宿主 Hook 注册类型和校验器约束命令参数、工作目录、作用域及秘密引用，已接入注册 UI 和执行器。

## 本轮阻断修复

已加入事件流、独立扩展库、表单/JSON 模板预览、Hook 注册/订阅/任务执行、回调原回答映射和基础显示重试。

- 代理交付仅接受宿主生成的反馈策略/提问人快照，不信任 CLI 正文提供的策略；未启用时保留旧路径。
- 普通群核验来源消息及群类型，不再强制话题回复；未绑定问题的群 ID 不用作消息 ID。
- 反馈卡回执、绑定和待清理内嵌控件原子保存；清理失败只重试 patch，不重发反馈卡。
- 模板快照负责反馈后重绘，保留任意插槽位置和竖排布局；Hook 状态与已有评价一起持久保存。
- 同时展示两种入口时，原回答与独立卡都进入状态刷新队列。
- 已发送但回执未知的 surface 可提交消息 ID，服务端核验应用/群/原问题/卡片内容后恢复绑定，不重发。
- 发送前在实际 transport 写入边界重新检查配置；移除的订阅不能继续执行已排队 Hook。
- 修复 Dashboard 忽略 bot 级展示配置、manager 无法绑定已批准动作、超大模板落盘及纯评价模板必需动作插槽的问题。

## 验收限制

- 发布前需核对同一 PR 最新 CI；不能把已证明的上游失败归为本功能通过。
- 普通群、代理、卡片状态和权限边界已有隔离组件/IPC回归，原生飞书客户端及真实账号四按钮验证尚未执行，需独立测试环境授权。
- 通用布局/素材控件支持仍以当前受校验模板 schema 为限；不接受任意回调或执行型卡片内容。
- 不把构建、限定审查或专项通过当作生产上线验收，也不承诺外部业务 exactly-once。

独立反馈卡不能作为新回答计入统计；预览/保存不能执行脚本；结果未知不能自动重复业务写入。默认不得改动运行中的配置、迁移共享反馈库或重启服务。

## 数据源约束

新增 `readFeedbackEventsAfter()` 提供顺序流：SQLite 增量触发器和 PostgreSQL 事务计数器。PostgreSQL 业务写入采用统一锁序；读流不取得业务写锁。主反馈库 user_version 保持 8，扩展业务状态单独存储。

存储后端切换后 generation 改变，消费者从新源起点读取，依靠稳定事件/操作身份避免重复副作用；序号不宣称跨后端保持一致。已安装流的 SQLite 迁移路径有真实临时 PostgreSQL 验证。
