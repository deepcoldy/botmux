# 定时任务的受控后台执行

在 Linux、非文件沙箱、共享本机 loopback、proven 身份模型的本地定时轮次中，可以登记一个后台任务，让它在原轮次结束后继续使用原执行人的受管 CLI 凭据。普通话题被调度器复用时也适用；普通真人对话轮不能借此登记定时身份。持久协调模式 disabled（默认）和 shadow 使用本地宿主权威；primary 的分布式关闭协议未承载该登记生命周期，注册和已有登记取票均拒绝，不复用本地关闭标记替代分布式权威。

```sh
botmux execution background --ttl-seconds 14400 -- python3 nightly_job.py
```

命令返回 JSON，包含 `jobId`、`pid`、`expiresAt` 与私有日志 `logPath`。默认登记 24 小时，最长 7 天；到期后需要在新的有效定时轮次重新启动。不要再用 `nohup` 包住这个命令，它会自行后台启动。旧的裸 `nohup` 进程不会被自动提升为已登记任务。

后台 supervisor 在启动工作命令前，先通过真实 socket 进程证明登记。启动者会等到登记成功且命令确实启动后才返回；拒绝登记不会执行工作命令。登记固定应用、会话、原始 scheduled fire、执行人、登录撤权代次、凭据策略、Linux boot ID、supervisor PID 与出生标识。只接受该 supervisor 的真实后代进程，不能用另一个会话、同 UID、环境变量或任意自报 PID 选取身份。

登记记录在宿主的 ScheduleAuthorityStore 中持久化，与既有调度权威存储使用相同信任边界；该存储须由宿主管理，不能暴露为受限会话的可写资源。这不是针对能篡改宿主权威数据库或直接读取宿主个人凭据目录的 OS 管理者的隔离机制。记录没有用户访问令牌，凭据正文仍仅存在 daemon 内存。

daemon 重启后从权威记录恢复登记，重新检查 boot/PID/出生标识、任务绑定、原执行人权限、登录代次和凭据策略，并按需重新签票。CLI 通过应用的最新 daemon descriptor 更新端口；descriptor 只供路由，不能替代真实进程证明。机器重启、supervisor 退出或工作进程脱离该 supervisor 的进程树后，登记不再可用。

每次取凭据在 provider 等待前后都检查授权。手动暂停/删除任务、更改任务内容或执行人、撤销原用户登录、变更凭据策略会使旧登记失效。恢复任务或重新登录不会复活旧登记；需要重新启动后台任务。已取出的凭据仍受提供方自己的有效期与撤销机制约束，本功能不承诺撤回已经执行的外部操作。

Cloud、Codebase 和所有实际存在的区域 JWT 分别检查过期，不以默认区域的寿命代替其他令牌。legacy Lark UAT 不含可解析过期声明，每次通过提供方重新解析；bound lark-cli 使用原有逐调用凭据路由。并发缺失合并为一次发布，晚到结果在授权变化后丢弃，不恢复原轮次或覆盖别的任务身份。

后台 bytedcli 的执行 HOME 是固定宿主根 `dirname(BYTEDCLI_HOME_ROOT)/background-jobs/<jobId>`，与会话 scratch 无路径交集，目录权限为 0700。普通真人轮仍使用主干的会话 scratch HOME。发布、退役清理与 scratch 沙盒封禁使用同一个绝对根，不从可变化的 `SESSION_DATA_DIR` 推导；core-only 默认根和自定义 state-dir 也封住这条路径，包括会话启动后才创建的目录。该实现自成一体，不依赖 #2572 的其他凭据根修复，也不更改那些既有封禁。

worker 退出清理 scratch 不删除 job HOME；daemon 重启后按需重建 job 目录并重新签票。撤销、任务暂停/内容或授权修改先持久退役，再仅删除该 job 子树；读取登记与新登记回收过期/死根时也重试清理，不删除其他活跃 job 的状态。任务位首条可见消息所物化的 rootMessageId、计数与下一次调度等运行期记账不改变 job 权威；编辑任务定义仍使旧登记失效。

静默定时轮结算、受信宿主的自动空闲清理可以关闭会话并删除 scratch，同时保留之前登记的 job。关闭行记录绑定本次 closedAt 的自动清理标记；只有已通过登记根证明的取票路径可使用它，不能在关闭后新登记，也不创建新轮次。手动关闭（包括对自动关闭行再次关闭）清掉标记并递增持久 session 代次；即使在下次取票前恢复会话，旧 job 的冻结代次也不匹配。未标记的旧关闭会话继续拒绝，普通 capability 请求不能伪造自动清理来源。

任务的原执行人在同一会话的有效轮次中可以显式撤销：

```sh
botmux execution background-revoke <jobId> --json
```

命令只撤销凭据登记；需要终止计算时，可向返回的 supervisor PID 发送停止信号。supervisor 会转发停止信号，工作命令正常退出或启动失败也会撤销登记。同一活进程根的撤销/过期记录保留为 tombstone，不能在旧轮次重新注册来恢复权限；已死根和过期任务不占用活动登记配额。单会话最多 64 个同时活动的登记。

自行 setsid 再次守护化的子孙可能逃出原工作进程组的停止信号；脱离 supervisor 血缘后不能取得登记凭据。SQL 退役后未被访问的内存凭据正文可保留到现有 terminal GC，但不再出票。daemon 重启后的真人自助撤销需要在同一会话的新有效轮次执行；任务暂停或删除也会退役登记。

自动完成的一次性任务、until-done 最终轮可在显式登记期限内收尾。delegated schedule、远程/adopt、网络隔离沙箱及不支持进程证明的平台继续拒绝该后台登记；它们的其他既有执行路径保持原行为。
