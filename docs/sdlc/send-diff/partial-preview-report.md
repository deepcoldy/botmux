# 超限 diff 部分预览修订报告

## 范围

需求讨论中反复修改文档时，用户需要看到Agent真实改动。超过2MiB的diff继续展示可解析的部分文件/行，每文件默认最多60行，并在面板底部加一小行灰字说明实际截断。

生产实现仍集中在src/cli.ts、src/im/lark/md-card.ts与技能定义，参数策略沿用send-policy.ts；没有新增独立卡片或命令模块。标题样式与原普通MD卡片一致，公共final守卫保持严格。

## 读取、解析与统计

通过FD读取最多2MiB+1字节判断超限，只解码前2MiB，保留UTF-8字符边界并在finally关闭FD。文件增长同样受最大读取量限制。

仅超大前缀模式容忍EOF未完成hunk或文件头；保留已读取的合法行，放弃未完成尾部文件头，非EOF格式错误仍拒绝。长行保留前段和省略号。

完整输入statsScope=full，展示截断时保留全量计数；超大前缀statsScope=preview，文件与增删计数只统计展示部分，未知省略文件数为null。60行包含hunk定位行，18KB预览预算可能进一步减少行/文件数，小灰字使用实际展示数。

## 摘要与链接

摘要过长时仅返回“摘要过长”和exit2，原卡片未发送。当前Agent按技能精简摘要/表格后重试，必要时省略摘要；程序不自动发送错误或兜底卡片，也不在CLI里调用模型。

文内链接作普通diff文本，不自动加入expected-link。文档入口在摘要交付，需要防漏时显式指定该入口；参数沿用整卡包含URL的检查，不强制只在摘要区匹配。

## 用例与验证

部分hunk、截断尾部header、60行和长行、UTF-8切口、最大读取预算、文件增长、final/@/回放和bounded relay均有行为验证。

标题回归同时断言原heading-2组件和无botmux_md_h标题ID。新增direct/host card-file、Codex/thread与Claude Code/chat四组用例，拒绝九类宿主/非法标题ID，每组使用真实生成diff卡确认同一发送上下文可成功。

- Vitest：13个文件464项通过，2项既有Linux专用用例在macOS跳过。
- 原生Bun：3个文件225项通过。
- host守卫旁路变异被2个host用例检出，直连仍拒绝；源码精确恢复。
- 覆盖率按技能条件跳过，无虚构统计；单测总结flush与当前分支完整构建通过。
