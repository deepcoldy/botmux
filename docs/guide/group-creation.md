# 建群默认配置与可选装饰

`/g`（别名 `/group`）建的群默认和群聊模式（私聊会话群）的专属群一样：用渐变 logo 头像，不写群名时按首条消息自动起名。还可以邀请本机部署的机器人、选择个人消息分组、改用含群名的文字头像：

```text
/g 项目讨论 --agents Review,Build,Check --tag 项目群 --avatar name
/g Project work --agents cli_review_app --tag "Project work" --dir ~/code/my-app --branch feat/demo
/g --card
/g --avatar off
```

`--dir <目录>` 为新群绑定默认工作目录（存入本机共享的 `created-groups.json`），新群内任意本机机器人开会话时优先使用该目录（优先级低于显式 `/oncall bind`，高于默认 Oncall、Bot 默认目录与同群继承）。配合 `--branch <分支>` 会先为该仓库创建独立 git worktree 并绑定到新群。

`--card` 弹出交互式建群卡片（下拉选择或手填工作目录、可选分支、可选群名，群名留空时沿用占位名与首条消息 AI 自动起名）。所有 `/g` 路径的成功、失败与前置校验错误均统一通过交互卡片回执（发送卡片失败时自动降级纯文本）。

`--agents` 接受逗号分隔的机器人显示名或 app ID；名称不区分大小写。机器人可以不在来源群内，但必须存在于本机当前 `bots.json` 配置中且启用飞书连接；`bots-info.json` 只辅助解析显示名，历史条目不参与成员选择。未知名称或重名会在建群前报错，重名时请使用 app ID。创建机器人始终保留。

每个 Bot 可在 `bots.json` 的对应条目配置默认值，也可使用 `/botconfig set groupCreation <JSON>` 修改：

```json
{
  "groupCreation": {
    "agents": ["cli_review_app", "cli_build_app", "cli_check_app"],
    "tag": "项目群",
    "avatar": "name",
    "card": true
  }
}
```

`"card": true` 开启后，不带群名/目录/分支/任务的裸 `/g` 会弹出建群卡片（默认 `false`，保持直接建群 + AI 自动起名的既有行为）；单次可用 `--no-card` 跳过卡片直接建群，或未开启时用 `--card` 单次弹出卡片。`--card` 不能与自动开工的任务（`--start`）同时使用。

显式参数覆盖相应默认值。命令有 `@机器人` 时继续由第一个被 @ 的机器人创建群，并补齐默认名单，按 app ID 去重。例如默认配置三个机器人时，只 @ 其中一个执行 `/g`，也会邀请整个组合。显式 `--agents` 替换默认名单，`--no-agents` 忽略默认名单，`--no-tag` 忽略默认分组，`--avatar off` 忽略默认头像。这些选项不会删除明确 @ 的机器人。

未配置 `groupCreation` 且未传选项时，只有当前机器人及明确 @ 的机器人入群。`--role-profile` 可以与上述选项组合使用。

`--tag` 指飞书**发起人个人侧边栏的消息分组**，不是租户共享的企业群标签。分组名最多 60 个 Unicode 码点。使用创建机器人对应应用下、属于命令发起人的用户授权；没有授权时群仍会建好，回执提示缺少授权。需要该应用开启用户权限 `im:feed_group_v1:read` 和 `im:feed_group_v1:write`，并完成 `/login --scope im:feed_group_v1:read im:feed_group_v1:write offline_access`。旧的无用户归属凭证不会冒充当前发起人。按名称复用分组；如果同名分组属于其他应用且不可访问，会明确报告失败，不会静默换名。

## 建群后 @ 群主提醒

新群建好、群主转给发起人之后，创建群的机器人默认会在群里 @ 群主发一条「群已创建，后续进展将在本群同步。」，让新群出现在对方的消息列表里。自动建群很频繁时（例如每个 PR 建一个评审群），可以整机关掉这条提醒，三种改法等价：

- Dashboard：设置 → 群聊创建 →「建群后 @ 群主提醒」。
- 命令行：`botmux create-group owner-notice off`；`on` 恢复，不带参数（或 `status`）查看当前状态。文件沙盒内这三种用法都会明确拒绝执行：那里读到的配置不代表宿主，写入也可能只落在临时文件系统；请改用宿主终端或 Dashboard。
- 配置文件：在 `~/.botmux/config.json` 顶层写 `"groupOwnerNotice": false`（必须是 JSON 布尔值）；删掉这一项即恢复默认开。

开关是本机全局的，对本机所有会发这条提醒的建群入口生效：`/g`（`/group`）、`botmux create-group`、Dashboard 建群与「创建会话」、Webhook 生命周期群、Dashboard 团队页拉群、会议监听群；团队页拉群延后转让群主时补发的那条单独 @ 也一并不发。团队页拉群在本机没有可用的建群机器人时会交给团队里另一台部署代建，这时按代建那台机器的开关算。关闭只去掉这条提醒，群主转让、邀请成员、设管理员、kickoff 消息照常。改完不用重启：下一次建群就按新设置执行（单次 `botmux create-group` 每次都读最新配置，daemon 最多约 2 秒读到新值）。

私聊转群（群聊模式的会话群）、`/relay --create`、`/fork --create` 和领取 issue 建群本来就不发这条提醒（会话群里 @ 发起人的引子消息是本轮回复的锚点，不受这个开关影响）；Dashboard 发起 Workflow 时建的话题群在任何设置下都不发。`botmux create-group --team` 由中心平台代建，平台自己发的「群已建好」@ 不归这个本机开关管。

## 自动群名

不写群名时，新群先用占位名「新会话 MM/DD HH:mm」（含全局前缀）。创建它的机器人处理到新群里第一条有内容的真人消息后，会用自己的 CLI 单次调用生成不超过 20 字的标题并改群名，与群聊模式的会话群命名相同。写了群名就以用户群名为准，不会再改。

- 斜杠命令（含 `@机器人 /status` 这种带 @ 的命令）、只有附件占位符（如 `[图片 1]`）的消息和机器人消息不作为命名依据。
- 配了 `--avatar name` 时，先按占位名生成文字头像，改名成功后按新群名重绘。
- 改名发生在群主转移给发起人之后，依赖群设置允许成员修改群信息（飞书建群默认允许）。机器人被移出群或无权修改时直接放弃；CLI 失败时按 30 秒、2 分钟间隔最多重试三轮，期间保留占位名。成员若已先手动改名，以手动群名为准。
- 多机器人群里只有创建群的机器人负责命名，命名依据是它处理到的第一条消息。
- AI 起名会在宿主上单独起一次 CLI，所以只在普通配置下启用：CLI 支持单次执行（与会话群 AI 命名相同），且机器人没开文件沙箱、宿主没启用设备凭证隔离、不是 Forge 启动方式、Codex 也没用私有或实例池登录。其它情况保留占位名。

## 头像

默认（`--avatar logo`）使用会话群同款的 botmux logo + 渐变底色，按群 ID 稳定地从十种配色中选一种，在建群时设置。`--avatar off` 保留飞书默认头像。

`--avatar name` 使用最终群名（含全局前缀）生成 360×360 PNG，按可用宽度换行并缩小字号，保留 Unicode 字素。复用截图的中英文字体配置，需要可选原生依赖 `@napi-rs/canvas`；Linux 中文字体由 `botmux setup` 安装到 `~/.botmux/fonts`。先完成机器人邀请，再在转移群主前设置头像；个人消息分组移到群主转移处理之后再写入，避免分组授权刷新把群主交接时间拉长（即便 transfer 失败，personal tag 仍会按本契约执行，失败独立不影响已建群）。

未知的 `--word` 不会报错，会原样保留到群名正文里，便于后续新增选项时老用户命令继续可用。已知 flag 只有在后面紧跟 `=`、空白或输入结束时才被识别：`--tag.foo`、`--avatar:off`、`--tagged` 等整体视为群名正文。需要让某个已知选项字样（如 `--tag`、`--avatar`）作为群名文字时，可以用一个独立的 `--` 作为选项结束符：`--` 之后的所有内容（包括已知 flag）都会进入群名正文；`--=foo` 不是 sentinel，会原样保留。已知选项仍强制校验：缺值、非法值、重复 `--option`、以及等号/空格 quoted value 后紧跟非空白字符（如 `--tag="A"suffix`）都会在建群前报错。

机器人邀请、个人分组或头像设置失败会在建群回执中单独提示；已创建的群不会因此重建。个人分组写入后会回读确认；授权刷新及分组 API 共用 10 秒超时预算。无头像配置的调用不会加载原生绘图依赖。
