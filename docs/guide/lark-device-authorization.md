# 飞书设备授权与多维表格只读查询

启用 `triggerUserAuth` 后，设备授权与登录态保存在当前发送者自己的 lark-cli HOME 中。首次设备登录的默认只读 Scope 包含 `base:field:read` 和 `base:record:read`，使读取表结构、查找记录和回读记录在同一次用户确认后完成。两项权限也进入用户 Scope 目录，`botmux auth request --scope "base:field:read base:record:read"` 不再被误判为 `unknown_scopes`。

签发应用需要先具备这些用户权限；应用权限配置不能代替用户本人同意。已有登录态不会因为升级而自动获得新 Scope。只读查询缺少权限时，应一次申请该查询实际需要的缺失项，不申请记录创建、编辑或删除权限。资源协作者权限仍由飞书检查，不能用换人、换应用或重新登录绕过。

设备授权由服务端返回设备码，并在用户确认后通过同一个设备码完成。Botmux 的单次等待上限是 30 秒；本地等待超时、网络错误或未知失败不证明设备码失效，保留尚在有效期内的请求，后续继续完成原授权。只有明确的授权拒绝、设备码无效或过期才清除请求。无论哪种失败，在用户登录态保存前都不放行用户身份操作。

这项改动不改变旧应用 OAuth 的默认权限、不改变 bytedcli 登录、不替用户同意授权，也不改变群内对话额度和管理员权限。初始授权、已有用户补权限和真实数据查询是不同的验证步骤；通过源码测试不能代替目标环境的整条消息链路验收。
