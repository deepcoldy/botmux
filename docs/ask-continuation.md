# 显式 Ask 的等待与接续

`botmux ask buttons` 等待真人回答期间，暂无输出是正常状态。Agent 应复用原等待进程直到回答或正常超时，不发送 Ctrl-C、kill，也不取消等待工具来提前收尾。命令等待期间拦截 SIGINT，并在 stderr 提示继续等待；会话的正式终止仍由宿主管理。

每次调用生成一个 requestId，连接暂时丢失时复用同一身份重连，不重复发卡。Daemon 将显式 Ask 作为自有的持久等待处理，保存原卡片身份和绝对期限。重启跨过期限时返回超时，不重新开始等待；超时、失效和传输失败都不代表批准。

回答先写入 broker 的持久结果，再转交到显式 Ask 回执。回执成功落盘后才清理 broker 结果，避免在两份存储之间丢失回答。缺失原持久记录时明确失效，不将旧请求当成首次创建。

命令输出结果后发送运输确认。若进程退出、结果未送达，后台保留回执，在原会话空闲且群/话题绑定仍匹配时，使用稳定的 follow-up turn key 接续；失败重试复用同一身份。恢复不创建新任务，不唤醒已关闭会话，不重派已完成业务。私聊不携带仅群聊允许的发送权限。

运输确认只证明结果已写入命令输出，不证明 Agent 已登记真人决定或业务任务已完成。接续方仍须回读原任务、问题、方案版本及当前范围，再消费对应决定；旧版本证据不能批准新范围。这一变更不迁移升级前已发出的 Ask。
