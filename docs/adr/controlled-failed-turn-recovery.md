# 受控失败恢复由 Runtime 保持身份和派发边界

状态：Proposed

## 问题

外部看门狗可以用既有 UI trigger 重投文本，但文本、话题和会话 Owner 不证明原失败轮次的发起人。先关闭再另行创建也无法与新消息竞争，可能覆盖用户已经继续的任务。

## 决定

提供一个宿主鉴权的失败恢复原语：daemon 冻结原轮次输入与可信身份，在既有 admission／mutation 生命周期中核对失败引用、权限和后续输入，先保存一次性回执，再恢复。轮询、错误分类和退避继续属于外部管理员进程。复用原有每轮工具身份准备和 Worker 入队，不新增独立身份解析器、消息平台或重试调度引擎。

不让外部调用者提供 caller、输入替换或 Owner 覆盖，也不让普通 Worker capability 成为宿主恢复授权。结果不确定时保留派发栅栏，不自动重发。

限流屏幕帧属于临时观察，只有未被认领且仍处于原生限流状态时可以恢复；成功、状态恢复或其他应用的身份均不能产生新的恢复授权。干净会话与正常 fork 共用冻结启动配置继承，路由归属由对应生命周期入口明确写入，不复制旧原生进程或会话 ID。

## 后果

接口只恢复有 daemon 身份证据的失败，旧记录不能补造证据；现场看门狗要在升级后核验真实 daemon 能力再启用。原会话、定时任务、沙箱与远程 backend 的既有行为不因新增原语而自动改变。接受派发与业务完成分开验收。协议与回执语义见[接口说明](../failed-turn-recovery.md)。
