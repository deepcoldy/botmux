# 真实入站消息在触发回合后独立续接

## 问题与边界

后台触发的 `trg_` 回合运行期间，真人消息可能被 CLI 的 type-ahead 路径吸收。消息的回复位置可以前移，但运行身份仍属于触发回合。此时创建检查点会被现有定时任务认证拒绝，符合合成回合不能充当人类请求的边界。

本次修复保留该拒绝规则。真人消息等待触发回合结束，以原 `om_`、原调用者及回复上下文开始独立回合，再使用既有定时创建路径。行为取舍是这些消息不再中途纠偏；普通真人回合之间的 type-ahead 保持原样。

## 实现

- 复用 `PendingCliInput.queueAfterActiveTurn`。只有活动回合为 `trg_`、输入为 `om_`，且宿主传入的调用者为普通用户时，增加串行约束。前缀与该约束只决定队列行为，不授予权限。
- worker 在 IPC 预检查、普通投递和 adopt 投递处保留该约束；写入前再次根据当前活动回合检查，防止排队期间身份变化或陈旧 ready 信号提前放行。
- 排队中的触发输入也不能与同调用者的真实消息拼接。既有独立消息 ID、原文、调用者和串行标记随队列保留；CLI 重启复用原队列恢复路径。
- adopt 互斥队列中尚未完成写入的触发输入也参与串行判定，避免较早消息藏在互斥队列、较晚消息进入可见队列后发生倒序。该集合只属于当前 worker，写入结束或失败即释放，不持久化，也不构成身份凭据。实际执行点再次核对活动回合，拒绝时走既有精确回队路径。
- 原回合到达终止边界后，真实消息经现有出队、进程标记和 daemon 回合登记路径执行。定时任务来源仍记录真实回合，无 `folded_human` 身份、无新增认证回退。

不修改 `isHumanInboundTurnId`、`registryTurnMayAuthenticateHuman`、进程树认证或 schedule/workflow 既有特殊路径。不从 marker 的 `inputConsumed`、环境变量或回复目标推断写权限，不增加配置或持久状态格式。

## 影响面与验证

队列约束位于共享 worker，覆盖采用该队列的 CLI 与后端；重点验证 TraeX、Claude、adopt 和 RPC 的现有串行入口。合成回合、机器人、未知调用者及恢复回合的认证边界保持不变。

行为回归覆盖：触发回合期间真人消息不出队；旧 ready 不释放活动回合；终止后仅执行一次；多条消息保持独立；CLI 重启保留队列；排队触发输入不能吸收真人消息。认证测试验证即使 marker 声称已消费真人消息，触发回合也仍拒绝，只有真实消息拥有独立回合后才能认证。

执行验证使用隔离 HOME、私有 tmux 和测试存储，不连接现役 bot，不修改生产配置或任务。实际命令与结果记录在 PR 描述中，未执行的验证单独列明。

## 回滚

整笔 revert 即恢复原队列策略，无数据迁移或配置回滚。已排队的消息沿用已有串行标记语义。修复不恢复历史已被吸收或已结算的消息，避免重放已经发生的副作用。
