# Codex 会话重连与原生思考区恢复

## 问题与行为

重启操作确认成功后，Codex 才补报原生会话 ID。该信息补充仍携带原重启操作 ID，曾被归为历史绑定，将同一个当前运行标记为 retiring。Worker 因此断开后端，后续消息留在队列中。

当前 Worker 对当前存活绑定补充身份时，不再沿用已结束的控制操作。若已有新的控制操作，则仅更新元数据并沿用当前操作归属，保持其状态和输入围栏，不确认该操作。物理进程及原生身份变更仍由存储层校验；关闭中的会话、旧运行或旧 Worker 不会被重新激活。

Codex 的非隔离托管 tmux 会话在 Worker 断开后保留 CLI。原生 CoT 现在复用已有的持久恢复记录，仅在应用、群、会话、原生会话 ID、tmux 目标及轮次匹配时续写原气泡。重连不发送失败完成请求；实际成功、失败、取消以及后续轮次替换仍按原协议收尾。

终态 checkpoint 必须先落盘再发送。写盘失败时保持未结算，并在存活进程中每秒重试；常规终态、旧批次失败的兜底完成及已禁用气泡的收尾共用这项守卫。定时器不延长进程寿命，原始状态由闭包保存，后续轮次不会覆盖它。落盘成功但 API 失败时，由已有孤儿扫描重试相同终态。

如果磁盘始终不可写且进程在重试前立即崩溃，内存中的新终态无法凭空恢复；本改动不承诺这一不可持久化窗口内的无损保证，也不把 UI 投递状态作为业务执行成败证据。

恢复后的原生完成记录可能先于运行绑定确认到达。桥接队列会保留这些完成记录，收到精确轮次的观察授权后再排出；不会重新提交输入。授权要求当前 Worker、活跃且无控制操作的会话、已写入但未终结的原轮次、可信的进程延续链，以及存活进程和原生会话身份一致。观察授权只允许接收原轮次的输出和终态，不授予执行或用户身份能力。

旧 journal 清理失败可能留下已终结轮次。若宿主的精确 execution/attempt 已结算且当前 Worker 不拥有它，则退休该旧记录，避免挡住后继结果；仍拥有的输出重试及未结算轮次保留原有投递和等待授权逻辑。

原轮次观察授权与后继输入可能交叠：绑定确认后，后继已经进入同一进程时，终态信封仍优先采用原轮次持久化的运行归属，仅在同一物理 CLI 的绑定中选择。不同进程上下文不会借用该归属。

Worker 断开时，属于其进程延续链的未终结轮次一起进入待核实状态。新 Worker 观察到的历史终态仅结算原轮次及其原卡片，不修改当前运行的就绪状态、队列或后继轮次。卡片 PATCH 失败保留原有可重试记录，不阻断业务完成回调。

## 影响与验证

- 会话绑定修复位于公共控制层；需要覆盖提前/延迟补报、数据库重开、进程身份变化及新关闭操作。
- CoT 恢复扩展仅增加 Codex；Antigravity 走相同回归矩阵。PTY、文件沙盒、读取隔离、外部接管及缺少原生会话 ID 的会话保留现有行为。
- 真实存储和桥接队列覆盖终态先于绑定确认、进程延续后断开、历史卡片收尾，以及进程/原生身份不匹配和控制操作中的授权拒绝。
- API 夹具模拟原生 CoT 终态不可逆，覆盖断开、晚到响应、部分批次失败、旧轮次和重试交叠；测试不会访问真实群或业务数据。
- 部署及真实验收记录单独留在开发机，不将真实会话、群标识或凭据写入仓库。
