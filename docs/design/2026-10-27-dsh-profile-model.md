# DSH 默认模型跟随所选配置（#2425）

## 问题与证据

DeepSeek Harness（DSH）的新版设置写入所选 profile（插件组合配置）。旧的
`settings.yaml` 只用于一次性导入，随后会被改名。botmux 仍单独读取这个旧文件，
导致 SDK 初始化请求中的 `provider`、`model` 与实际插件组合不一致。

- 问题：[GitHub #2425](https://github.com/deepcoldy/botmux/issues/2425)。
- 基线：`0e9583899`，原有 `test/dsh-runner.test.ts` 的 32 个测试全部通过，但只覆盖旧设置。
- 核对 `@deepseek-ai/dsh@0.2.1-rc.2` 发布包：`--dump-config` 使用与启动相同的配置合成算法，
  包含组合包、profile、DSH_HOME 下的全局覆盖和命令行 `--patch`；不启动插件，也不执行 `!!js`。
- 默认模型对应合成配置树中的 `id: agent-default-model`，模型选择位于该项的 `config`；
  该项可以位于分组内部，不能只查顶层列表。
- 新版在启动插件后才导入旧设置，`--dump-config` 不执行迁移。因此版本号不能用来判断
  旧文件是否已经失效；首次升级时仍需保留旧文件中的明确选择。

## 方案

1. 保留现有 profile 准备和凭据加载逻辑。先构造运行目录、环境及启动参数，
   配置查询与实际 DSH 子进程共用这些值，避免补丁、DSH_HOME 或工作目录不一致。
2. 启动 SDK 前执行同一 DSH 二进制的 `--dump-config`，设置超时和输出大小限制，
   不经过 shell。查询失败直接中止，不读取旧文件来掩盖错误。
3. 使用仓库已有 YAML 解析器。将 `!!js` 保留为不执行的表达式对象，允许其它插件含有表达式，
   但默认模型项的启用状态、配置、提供方或模型不能依赖动态表达式。
4. 递归遍历声明为分组的 `config`，并继承父分组的启用状态；空分组合法，其它插件的数组
   配置不当作插件列表。默认模型不存在时沿用原内置默认值；跨分组的重复项也会报错。
5. `settings.yaml` 仍存在时，其明确设置的提供方、模型继续覆盖合成配置，未设置的字段
   使用合成配置；空文件不提供覆盖值。旧版运行时读取该文件，新版首次启动会导入该文件；迁移由 DSH 自己完成。
   文件被改名为 `.imported` 后，后续启动只读取合成配置，不再读取旧备份。
   旧文件直接读取，不先判断是否存在；读取时文件刚好被 DSH 改名，按文件不存在处理。
   `--model` 最后覆盖模型，不改变提供方。不查询版本，也不依据版本猜测迁移状态。
6. 配置无效、默认模型重复，或默认模型及其父分组被禁用时明确报错。错误不包含配置正文、查询输出或凭据。
   DSH 的解析错误会附带配置文件的上下文片段，可能带出密钥，因此查询失败时不转发子进程输出，
   而是给出一条可直接运行的完整查询命令（包含 profile、补丁，以及非默认的 DSH_HOME），
   由使用者在本机查看原始错误。
   启动诊断只记录 profile、提供方、模型，以及两项各自的选择来源。

## 影响范围

- 仅调整 `dsh` 启动器的模型选择，不修改公共命令路由、工作进程、会话存储或凭据契约。
- `dsh-tui` 及其它命令行适配器保持原启动路径。
- 话题、群、恢复会话经过同一个启动器，均采用启动时的配置；不修改恢复或持久状态语义。
- PTY 与 tmux 后端都启动同一程序。配置查询在同一沙盒、工作目录和环境中运行，
  不增加路径挂载或执行权限。macOS 与 Linux 使用无 shell 的子进程参数数组。
- 不新增依赖；YAML 静态导入可被 Bun 单文件构建打包。
- 版本比较与更新检查不属于本次改动；无需抽取公共版本工具，运行代码的修改限于 DSH 启动器。

### 存量用户的行为变化

- **未配置模型的会话改用 DSH 自带的默认模型。** 条件是：没有旧版 `settings.yaml` 或其中未设置模型、
  bot 配置未设置 `model`、profile 未修改默认模型。botmux 自动生成的 `botmux` profile 不设置默认模型，
  因此只配置了 `DEEPSEEK_API_KEY` 的用户都属于这一类。这些会话从 botmux 内置的
  `deepseek-official / deepseek-v4-flash` 改为 dsh-base 自 0.1.5 起自带的 `deepseek-official / deepseek-flash`；
  dsh-base 0.1.1 自带的仍是 `deepseek-v4-flash`，使用该版本的用户不受影响。提供方和凭据不变。
  DSH 0.2.1-rc.2 的官方模型列表中，`deepseek-flash` 对应 DeepSeek-V4.1-Flash 并支持图片输入，
  `deepseek-v4-flash` 已不在列表中，DSH 会把它当作只支持文字的未知模型。改动后与直接运行 dsh 时一致，
  这是本次修复的目标，因此接受这一变化。需要保持旧模型时，在配置卡中选择 `deepseek-v4-flash`，
  或在 bot 配置中设置 `"model": "deepseek-v4-flash"`。
- **profile 改了提供方、同时 bot 配置显式设置模型的会话改走 profile 中的提供方。** 改动前这些会话
  实际走官方接口；改动后模型名不变，提供方取 profile 中的设置。该提供方没有这个模型时，会话初始化可能失败。

## 验证计划

- 在真实启动器与假 SDK 服务之间捕获 `initialize`，先证明旧实现错误，再验证修复。
- 覆盖旧设置尚未迁移及迁移后再次启动、切换 profile、自定义 DSH_HOME、补丁、显式模型覆盖、
  旧设置缺少部分字段、嵌套分组、父分组状态、重复项、查询失败、动态值及诊断不泄露凭据。
- 使用真实 DSH 0.2.1-rc.2 验证配置合成；在隔离目录和本地模型接口中完成一轮请求。
- 执行相关适配器和工作进程回归、`bun run build`，并按仓库要求验证 daemon 重启。
- 提交中文说明的 GitHub 合并请求，列出实际验证结果与未覆盖边界。

## 验证结果

- 回归先失败：旧实现发送 `deepseek-official / deepseek-v4-flash`，而测试要求合成配置中的
  `flatkey / deepseek-v4-1-flash-1017`。修复后相同测试通过。
- 相关 9 个测试文件：682 项通过，1 项按环境条件跳过，涵盖启动器、工作进程、
  其它命令行适配器、版本比较以及测试规范。
- 真实 DSH 0.2.1-rc.2：`test/dsh-profile-model.e2e.ts` 四项通过。使用临时配置目录和
  本地 OpenAI 兼容流式接口，验证配置切换、补丁、显式模型、首次迁移、迁移后修改配置并再次启动，
  以及分组中的默认模型。涉及请求的场景均完成真实 SDK 请求。
  请求使用自定义路由和凭据文件中的测试密钥，环境未设置 `DEEPSEEK_API_KEY`。
- 变异验证：临时移除旧设置优先级和分组递归后，单元测试与对应真实运行时测试均失败；
  忽略父分组状态、删除重复项检查，或破坏空配置及原生分组识别后，对应单元测试也失败。
  恢复代码后重新验证全部相关测试。
- `bun run build` 通过。另将 `src/dsh-runner.ts` 单独编译为 Bun 二进制，
  在尚未迁移和分组配置两种场景下，分别完成配置查询、SDK 初始化和一轮假服务请求，
  确认 YAML 解析器与新增模块可被打包。
- 查询失败提示：单元测试在自定义 profile、带空格和单引号的补丁路径、自定义 DSH_HOME 下触发查询失败，
  再在另一个目录、不带外部 DSH_HOME 的环境中运行提示中的命令，确认它发出相同的查询参数和 DSH_HOME。
  去掉 DSH_HOME 前缀或参数转义后，该测试均失败。真实 DSH 0.2.1-rc.2 中写坏补丁文件后，
  运行提示中的命令可以看到 DSH 的原始解析错误。查询失败的各个用例也改为断言具体的失败原因。
- 隔离配置目录中执行 `bun run daemon:restart` 成功，状态查询确认管理服务在线，随后停止。
  该目录没有配置真实机器人，因此这项仅验证管理服务重启，不代表 daemon 的飞书路径已实测。
  现有 3.22.0 线上服务未切换；本地未覆盖 Linux 沙盒或飞书端到端交互。

## 复核问题与回归证据

| 级别 | 场景与修复 | 探针证据 |
| --- | --- | --- |
| P1 | 新版首次启动尚未迁移旧设置；按版本排除旧设置会提前选中官方模型。改为按文件是否仍存在保留明确选择。 | 真实 DSH 中原方案报缺少官方密钥；修复后首轮自定义模型请求成功，迁移后修改配置并再次启动使用新模型。 |
| P2 | 默认模型处于分组内部；只查顶层会误用内置默认值。改为递归读取并继承分组状态。 | 真实组合包中将默认模型移入分组，原方案返回官方默认值；修复后配置查询与 SDK 请求均使用自定义模型。禁用、动态父分组状态及跨层重复项均被拒绝。 |

真实 DSH 验证可重跑（依赖安装位置必须位于工作区之外）：

```bash
mkdir -p /tmp/botmux-dsh-runtime
bun add --cwd /tmp/botmux-dsh-runtime --exact @deepseek-ai/dsh@0.2.1-rc.2
BOTMUX_TEST_DSH_NODE_MODULES=/tmp/botmux-dsh-runtime/node_modules \
  bun run test:e2e -- test/dsh-profile-model.e2e.ts
```
