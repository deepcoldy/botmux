# DSH 默认模型跟随所选配置（#2425）

## 问题与证据

DeepSeek Harness（DSH）的新版设置写入所选 profile（插件组合配置）。旧的
`settings.yaml` 只用于一次性导入，随后会被改名。botmux 仍单独读取这个旧文件，
导致 SDK 初始化请求中的 `provider`、`model` 与实际插件组合不一致。

- 问题：[GitHub #2425](https://github.com/deepcoldy/botmux/issues/2425)。
- 基线：`0e9583899`，原有 `test/dsh-runner.test.ts` 的 32 个测试全部通过，但只覆盖旧设置。
- 核对 `@deepseek-ai/dsh@0.2.1-rc.2` 发布包：`--dump-config` 使用与启动相同的配置合成算法，
  包含组合包、profile、DSH_HOME 下的全局覆盖和命令行 `--patch`；不启动插件，也不执行 `!!js`。
- 默认模型对应合成列表中的 `id: agent-default-model`，模型选择位于该项的 `config`。

## 方案

1. 保留现有 profile 准备和凭据加载逻辑。先构造运行目录、环境及启动参数，
   配置查询与实际 DSH 子进程共用这些值，避免补丁、DSH_HOME 或工作目录不一致。
2. 启动 SDK 前执行同一 DSH 二进制的 `--dump-config`，设置超时和输出大小限制，
   不经过 shell。查询失败直接中止，不读取旧文件来掩盖错误。
3. 使用仓库已有 YAML 解析器。将 `!!js` 保留为不执行的表达式对象，允许其它插件含有表达式，
   但默认模型项的启用状态、配置、提供方或模型不能依赖动态表达式。
4. 合成配置中的默认模型优先。仅当该项不存在时读取旧 `settings.yaml`，
   保留无配置时的默认选择。另一个经过发布包确认的边界是：0.1.1-rc.1 已有同名插件项，
   但运行时仍由旧设置覆盖。两者同时存在时查询 `dsh --version`，只有早于
   `0.1.7-alpha.1` 才保留旧设置的优先级；无法确认版本则报错，不猜测格式。
   `--model` 最后覆盖模型，不改变提供方。
5. 配置无效、默认模型重复或被禁用时明确报错。错误不包含配置正文、查询输出或凭据。
   启动诊断只记录 profile、提供方、模型，以及两项各自的选择来源。

## 影响范围

- 仅调整 `dsh` 启动器的模型选择，不修改公共命令路由、工作进程、会话存储或凭据契约。
- `dsh-tui` 及其它命令行适配器保持原启动路径。
- 话题、群、恢复会话经过同一个启动器，均采用启动时的配置；不修改恢复或持久状态语义。
- PTY 与 tmux 后端都启动同一程序。配置查询在同一沙盒、工作目录和环境中运行，
  不增加路径挂载或执行权限。macOS 与 Linux 使用无 shell 的子进程参数数组。
- 不新增依赖；YAML 静态导入可被 Bun 单文件构建打包。
- 将既有版本解析和比较函数原样移至独立工具模块，更新检查模块保留原导出，
  避免启动器仅为比较版本而加载更新下载、会话存储等无关模块。

## 验证计划

- 在真实启动器与假 SDK 服务之间捕获 `initialize`，先证明旧实现错误，再验证修复。
- 覆盖旧设置已迁移、与新配置冲突、切换 profile、自定义 DSH_HOME、补丁、显式模型覆盖、
  旧格式、查询失败、无效配置、动态值，以及诊断不泄露凭据。
- 使用真实 DSH 0.2.1-rc.2 验证配置合成；在隔离目录和本地模型接口中完成一轮请求。
- 执行相关适配器和工作进程回归、`bun run build`，并按仓库要求验证 daemon 重启。
- 提交中文说明的 GitHub 合并请求，列出实际验证结果与未覆盖边界。

## 验证结果

- 回归先失败：旧实现发送 `deepseek-official / deepseek-v4-flash`，而测试要求合成配置中的
  `flatkey / deepseek-v4-1-flash-1017`。修复后相同测试通过。
- 相关 9 个测试文件：678 项通过，1 项按环境条件跳过，涵盖启动器、工作进程、
  其它命令行适配器、版本比较以及测试规范。
- 真实 DSH 0.2.1-rc.2：`test/dsh-profile-model.e2e.ts` 两项通过。使用临时配置目录和
  本地 OpenAI 兼容流式接口，验证配置切换、补丁、显式模型，以及一轮真实 SDK 请求。
  请求使用自定义路由和凭据文件中的测试密钥，环境未设置 `DEEPSEEK_API_KEY`。
- 变异验证：临时删除配置查询失败的检查后，对应测试失败；恢复检查后重新验证。
- `bun run build` 通过。另将 `src/dsh-runner.ts` 单独编译为 Bun 二进制，
  真实执行配置查询、SDK 初始化和一轮假服务请求，确认 YAML 解析器与新增模块可被打包。
- 隔离配置目录中执行 `bun run daemon:restart` 成功，状态查询确认管理服务在线，随后停止。
  该目录没有配置真实机器人，因此这项仅验证管理服务重启，不代表 daemon 的飞书路径已实测。
  现有 3.22.0 线上服务未切换；本地未覆盖 Linux 沙盒或飞书端到端交互。

真实 DSH 验证可重跑（依赖安装位置必须位于工作区之外）：

```bash
mkdir -p /tmp/botmux-dsh-runtime
bun add --cwd /tmp/botmux-dsh-runtime --exact @deepseek-ai/dsh@0.2.1-rc.2
BOTMUX_TEST_DSH_NODE_MODULES=/tmp/botmux-dsh-runtime/node_modules \
  bun run test:e2e -- test/dsh-profile-model.e2e.ts
```
