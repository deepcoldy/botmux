# 自动共享的会话范围

自动补充以当前主对话或具体话题为边界，不把同群其他话题当作候选背景。主对话保留平铺消息和普通引用回复；话题只提供该话题起始消息及有归属证据的本话题消息。显式引用、history/quoted 查询能力保持原状。

## 归属证据

`root_id` 是回复关系，不能单独证明消息在话题内。`thread_id` 是原生话题标识；原生话题起始消息可以有 thread_id 而无 root_id。自动共享选择器接收主对话／话题、可选 rootId 和原生 threadId，独立于可能把话题折入同一个模型会话的 reply-mode。

共享日志新增 nullable `conversation_scope`（schema 4）。实时消息、权威群历史、真实话题容器和实际发布目的地提供归属信息。发送回执缺少字段时不猜测：已有话题中的回复即使未指定 reply_in_thread=true，也可能仍在话题内；使用回执或目标消息的明确话题证据。目标过去在主对话不能证明它后来未成为话题起始消息，所以稀疏回复回执不会据此标为主对话；未知则保留 parent_id 等关系等待补齐。

同一消息跨修订保留已知归属。先前明确在主对话的起始消息即使后来成为话题根，仍可留在主对话；在其话题里也作为起始消息保留。先前已有原生话题证据的消息，不会因为后来一个稀疏回执而降为主对话。

## 筛选顺序

从全部同群版本恢复稳定归属证据，同时按当前请求截止时间单独筛选可提供的正文。后来版本可以证明旧正文属于话题，但不能把后来正文提前提供。会话筛选在附件读取和正文排序之前执行；渲染器复用相同证据再防守一次。原先为了多样性保留其他话题来源的规则已移除。

历史话题读取区分真实 thread 容器与按 root_id 的群扫描兜底。只有真实容器能补充确定的话题归属，兜底扫描不能把主对话引用误认成话题。

## 兼容与限制

主对话只接受明确归属 main 的消息；旧记录即使看起来平铺、没有 root_id／thread_id，也不能把字段缺失当作主对话证明。无法确定归属时暂不自动共享，待实时事件或权威历史补齐。这样也覆盖初始状态卡不入正文日志、最终 PATCH 回执又缺少路由字段的情况。

已经输入模型的旧背景不能收回，不主动重置用户会话。原有会话路由和回复模式不变；如配置了多个话题共用原生模型会话，已有模型记忆不会因本次自动补充过滤而拆分。

不改变群共享开关、权限、增量交付回执、暂停期间历史回补规则或手动跨话题读取。
