# 插件敏感结果的宿主读取边界

## 目标与边界

安装在本机的可信 stdio 插件可声明 `readPolicy: receipt-only`。宿主直接向
可信原会话交付卡片与附件，只向模型返回脱敏回执；后续宿主消息读取不得
把正文、原始卡片、资源 key 或文件重新交给编排模型。未声明的新旧插件仍
走原有结果入口，不能因本功能改变默认交付可见范围。

本功能不是跨飞书平台的 DLP，也不能撤销已经进入模型上下文的历史数据。
任意外部凭据、未托管 API、人工复制正文或拥有宿主私有目录权限的进程不在
消息来源标签的覆盖范围。生产隔离还要求受限模型进程、私有结果目录、
受控网络与凭据；不能把宿主读取测试等同于这些部署前提已经验收。

保护模式在 `bots.json` 显式配置 `protectedResults: true`、`sandbox: true`（oncall），
并要求本地 macOS/Linux 文件沙箱、托管工具绑定和凭据隐藏。该会话
不再向 CLI 导出飞书用户/应用凭据，也不允许通过 profile/native 分支绕过。
读取普通文本使用受控 history/quoted，查询结果验收使用宿主脱敏状态工具。
应从新建干净会话启用，不支持把已泄露的上下文通过热更新变成隔离上下文。
Windows、scratch/off、远程/未托管或 workflow 会话不提供该能力，插件必须在查数前检查
`result_delivery_receipt_only_v1`，不可退回把正文传给模型的旧交付方式。

## 生成与交付的职责

通用主线是“插件内的结果生成组件 → 宿主可信交付 → 用户”。生成完成后，
插件把产物通过已有 MCP 工具返回通道交给 Gateway，worker 再通过既有 IPC
请求 daemon 投递。中间转交不意味着重新查询数据或重新调用模型；正文、
图表和文件不会为此交回编排模型。插件不持有飞书发送凭据或自行选择任意
接收目标，宿主统一校验目标和产物、登记状态与防重。接入方应复用这条
通用协议，不为某个结果生成组件新增绕过校验的直连发送接口。

## 交付状态

敏感正文不写入保护索引；索引只含受信应用、插件、用户、会话、turn、目标、
payload 指纹、消息/资源 ID 和状态。索引按群跨应用共享，以便另一应用的
受控历史查询也无法读回敏感结果。索引不随文件 TTL 自动删除：消息可能
在平台上长期存在。容量不足或索引损坏时拒绝进一步敏感投递/读取。

发送前持久化 pending 记录。所有文件先校验和上传，再发送附件，最后发送
结果卡作为完成标记。每个可见消息都在确认后记入索引；只有全部完成才
把状态写为 delivered，解除未知消息的读取围栏，已标记消息仍不可读。

上传与可见发送都属于外部副作用。上传前持久化资源登记意图；上传接受后
只有资源 key 已落盘才能清除此意图。上传 ACK 丢失、key 登记失败等异常保留
pending/unknown；未完成资源登记期间，所有群的资源读取与资源型消息均保守
遮蔽，避免复制到另一群绕过围栏。已知资源登记完成后仍按 key 保护。

仅在未进入任何外部副作用且无消息时记录 aborted；相同 ID、相同指纹的
aborted 重试在锁内重新置为 pending。pending/unknown 不随时间自动重试。
完成后同 ID、同指纹只返回既有回执；不同指纹拒绝。指纹使用带版本的
JSON manifest，明确记录正文、文件顺序、名字、字节数及逐文件 SHA-256，
避免分隔符与二进制内容相混。旧指纹记录不自动迁移或重发。

最终卡片与 Markdown 引用的图片/文件 key 也必须在发布前登记；登记失败
不得发布。结构化回执保留每条消息的 primary/attachment 类型，不能把部分
附件成功误记为正文成功。

原始 IM 详情、列表、quoted/raw、附件下载和自动事件解析复用同一检查。
接收事件在路由前生成统一遮蔽副本，监听匹配、晚刷新及群上下文入库均消费
此副本；保护索引失败不能按普通解析失败退回原始正文。
受保护消息只返回元数据与占位符，过滤在关键词筛选、原始 JSON 展开和
附件下载之前。复制的受保护资源 key 同样拒绝读取。转发树没有可靠来源
证明时失败关闭，不能把未知来源当成普通文本。当前采取保守策略：本机已有任何
保护索引时，所有不透明合并转发树均被遮蔽，包括其他群的转发；普通文本仍可读取。

## 状态与单次交付

`botmux_result_delivery_status` 是宿主工具，按 Gateway 可信真人、应用和
会话查找结果。模型只能给插件 ID 和 delivery ID，不能指定用户、应用、
会话或文件路径。返回固定状态、原目标与消息 ID、附件数量，不调用插件
数据查询，也不返回业务正文。机器人触发或身份缺失拒绝。

已完成的受保护结果拥有本轮 final；编排模型再次 final 时只确认已有投递，
不再发送其摘要或附件。CLI 显式 final 与 worker 自动 final_output 均检查
同一应用/会话/turn 的完成记录，排队等待后再次检查；auxiliary 不占用 final。普通请求和未完成请求不能被误判为已成功交付。

## 验收面

需覆盖人工中途换权/取消、provider 接受后落盘或 ACK 失败、长上传与重启/
查询交叠、跨用户/应用/会话状态访问、不同投递并发、损坏/符号链接索引、
原始 JSON/转发/附件回读和重复 final。故障探针使用真实组件与可控时钟；
移除关键守卫应使行为测试失败。只使用合成数据。

## 异常处置与调用开销

pending/unknown 表示发送结果尚不能确认，不是允许重试的错误。先使用
`botmux_result_delivery_status` 获取当前调用者绑定的状态和已知消息 ID，再由
有权限的运维人员核对 provider 回执、投递日志和原目标。没有完整送达证据时，
保持读取围栏；不得按时间自动解封、改换 delivery ID 重发、删除保护索引或
手改状态冒充成功。本版本尚未提供安全的 reconcile 写入接口；受控恢复需
另行定义证据、权限和并发校验，不能用跳过保护的临时开关替代。

存在保护索引时，附件下载会先查询消息归属群，再判断是否落在未确认投递的
围栏中。这会增加一次消息详情 API 调用，是保守保护的明确代价；后续优化
必须证明跨群、复制资源与 pending/unknown 保护仍成立，不能直接删掉归属校验。
