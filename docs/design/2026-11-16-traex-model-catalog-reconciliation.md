# TraeX 自动模型池与实时目录对齐

状态：已实现并完成本地隔离验证；未部署到线上。

## 判断边界

- 只有完整、非空、成功分页到末尾的原生 `model/list` 可以确认候选模型缺失。
- 超时、鉴权失败、空响应、分页不完整或协议异常不能推断模型下线。
- 按当前账号、CLI 和 provider 的目录判断；不推断模型全平台下线。
- 完整目录确认缺失后，先提醒，再永久删除保存的模型池条目和该模型独立设置；保留其余模型的顺序与设置。
- 模型以后重新出现也不自动加回，需用户明确重新配置，不扩大用户模型池。

## 查询时机

- 受支持的 Auto 新启动、冷恢复在启动真实 CLI 前查询一次，校验将要启动的模型。
- 排队达到该 Bot 配置的持续排队阈值、实际准备换模型时再次查询。
- 短暂排队、逐帧终端刷新、忙碌回合追加消息不额外触发查询。
- 同一 Agent 同一时刻最多一项目录查询；取消、换配置和运行世代变化使旧结果失效。

## 通知

- 确认排除候选时，在应用替代选择前通知受影响会话，列出被排除模型及处理方式。
- 自动处理不额外要求确认，通知须明确是永久清理，不保证替代模型免排队。
- 同一选模流程的同一缺失集合只通知一次，避免刷新和重试重复刷屏。
- 若用户模型池与有效目录交集为空，明确停止选模，不创建全新历史、不扩大模型池。

## 查询失败的重试

- 单次查询默认最长 8 秒。
- 启动首查失败时保留原模型继续启动，不让目录重试阻塞健康模型；后台只在启动/输入尚未完成或仍排队时重试，开始正常工作即停止。
- 失败结束后间隔 30 秒重试，一轮总共最多 3 次，包含首次查询。
- 仅在该选模流程仍有未完成需求时重试；取消、关闭、配置变化或模型已正常继续工作后停止。
- 三次仍失败，保留配置并结束本轮目录清理，通知无法核实，不以未核实候选替代已工作的模型。
- 后续独立新请求重新启动查询；不创建常驻定时扫描或无限重试。

## 验证范围

- 首选或备用模型缺失、大小写及公开别名匹配、缺失负载但模型存在。
- 空目录、鉴权失败、超时、分页失败及重复游标不触发候选清理。
- 冷恢复保留原生会话 ID；失败候选不被重复启动。
- 单飞查询、30 秒间隔与三次总上限、人工取消及配置世代失效。
- 通知去重、查询失败保留配置、模型重新出现后不自动加回。
- 永久配置写回只修改目标 Bot 和已确认缺失条目；并发人工修改不得被旧目录结果覆盖。
