# Ask 按题自定义输入

普通 Ask 在每题选项之后提供“其他／自定义”输入框，最后统一提交。填写文字替代本题选项，其他题的选择保持不变；重新点击本题选项会清空本题文字。单选、多选和文本题可以混合。

使用 Card JSON 2.0 的 `form`、`input` 和 `form_submit` 按钮，不使用旧版曾被飞书静默丢弃的 form/select 组合。所有选项按钮都会带上完整表单字段，服务端在同一次操作里保存选择和文字；草稿不是正式答案。单题最多 1000 个 UTF-16 字符，全批最多 2000，另外在写入前核对卡片请求体预算。尚未触发按钮回调的本地输入没有落盘。

## 数据与边界

- `AskQuestion.allowCustom:false` 关闭本题自定义。普通 explicit、host_explicit、hook、native-user-input、native-user-input-async 默认提供。其他 host 审批保持闭选；Claude 权限审批和暂不支持混合文字回灌的 CoCo picker 显式关闭。
- `answers[i]` 继续只放选项 key；`customAnswers[i]` 是该题的文字或 null。自定义题的 `answers[i]` 为空。旧话题文字回复仍走整卡 `comment`。
- CLI `--json` 输出新增可选 `customAnswers`，普通选项输出形状不变；非 JSON 输出仍只承载 key，并在有按题文字时提示读取 JSON。
- Claude、OpenCode、DSH、Codex 同步/异步输入按题消费文字，原始问题身份不变。explicit receipt 与原会话恢复透传完整结果。
- 单问也需最后提交；默认推荐选项仍只是草稿。权限审批保持原选择方式。

## 状态与恢复

`customRevision` 与按题文字、选项一起持久化。每次表单回调先校验 bot/card、nonce、答复权限、revision、所有字段和大小，全部通过才写入。草稿先落盘再更新内存，写失败不确认成功；旧 revision 返回当前卡片供用户重新确认。旧版按钮不能覆盖已产生的新版表单草稿。

空多选二次确认先保存用户刚清空的草稿，避免旧文字复活。问题身份比较包含自定义许可，重连不能更换规则复用已有答案。超时、取消、原会话、幂等身份和可靠接续规则继续生效。

## 验证

行为测试覆盖混合提交、默认选项、跨题保存、换回选项、文字限制、卡片大小、越权、旧 nonce/revision、重复提交、人工取消、超时、重启与断线恢复、部分写失败、统一实时卡的异步更新、真实 CLI JSON stdout，以及多 CLI 的答案转换。

飞书 CardKit 创建接口接受双题完整表单（仅创建卡实体，未发群消息）；此检查证明平台接收卡片 schema，不等于飞书客户端已完成真人点击验收。

本次定向回归共 21 个测试文件、427 项通过，Bun 1.4.3 完整构建通过。独立故障探针发现并修复：空确认恢复旧文字、自定义许可未参与请求身份、超限草稿无法重绘、旧卡升级后丢响应无法接续。对身份校验、空确认保存、草稿写入、strict 落盘分别做守卫变异，四项均使对应测试失败，恢复后回归通过。
