# 飞书回复中的本机地址策略

飞书用户在自己的客户端阅读机器人回复，无法把开发机文件路径当作交付链接。仅校验 Markdown 闭合或 HTTP 链接完整性无法防止这类回复：

```text
协作说明：通过 [协作技能](/home/example/.agents/skills/collaboration/SKILL.md) 联系其他机器人。
```

处理后保留“协作技能”名称。源码绝对路径位于已知工作区时转为仓库相对引用；其他文件或本机服务引用改为内部文件说明。报告应通过附件或真实可访问的远程链接交付，策略不会生成远程地址。

## 处理规则

`src/im/lark/local-address-policy.ts` 提供文本、结构体与消息体三个入口。识别常见 Linux/macOS 文件根目录、当前用户目录与工作区、Windows 驱动器与 UNC 路径、文件与编辑器协议、回环地址、实际主机名和网卡地址；正文里的主机名只在 `主机名:端口` 或 URL 主机位置识别，与主机名同形的普通单词保持原样；IPv4 映射的 IPv6 与 URL 解析器接受的特殊写法适用相同限制。远程链接的查询、路径或片段里嵌着本机地址时（飞书客户端打开链接、登录跳转等包装，含多层编码），整条链接按本机地址处理。

- Markdown 技能链接保留名称；工作区源码链接变为相对引用；其他本机链接保留标题并说明没有可访问链接。
- 模型输出入口（见「接入位置」）处理的正文、代码、摘要、标题和表格使用同一文本策略；引用式链接、编码的目的地址和未闭合本机链接也会处理。
- 正文里不指向用户文件的系统路径保留原样：`/dev/null`、`/dev/stdin`、`/dev/stdout`、`/dev/stderr`、`/dev/fd/<n>`，以及 `/proc`、`/sys` 下的路径，名单写死在策略模块里。`/proc` 下进程的 `cwd`、`root` 会回到文件系统，其下的路径仍按本机路径处理；同一条消息里的用户文件路径照常替换。豁免只作用于正文，Markdown 链接目标和卡片链接字段不受影响。
- `url`、`href` 及平台跳转字段指向本机时，在 SDK 调用前抛出稳定的 `LOCAL_ADDRESS_OUTBOUND_REJECTED` 错误，错误消息不回显原地址。宿主自己构造的 Web 终端与 Dashboard 等页面链接例外，见「投递失败与兼容性」。
- 卡片回调 `value`、协议身份与媒体 key 保持原用途；原始输入对象不被修改。Feishu Markdown 中的原生图片 key 也保留。
- 合法远程 URL 保持原始字节，包括业务 URL 内的文件状查询参数；紧贴前缀的 URL（如 `git+https://…`）按外层整体只处理一次。API 路径与普通相对源码文本保留，不用 RFC1918 范围代替主机身份判断，也不查询 DNS 或文件是否存在。
- 安全的 JSON 保留原始字符串；模型输出入口拒绝含本机地址的畸形 JSON，安全的畸形 JSON 以及传输层见到的畸形 JSON 交给原有 provider 校验。

## 接入位置

正文替换只在模型输出入口做：`botmux send`、自动 final、unified 回复卡和原生思考消息（CoT），以及自动文档评论。这个策略要防的是模型把打不开的本机地址交给用户，不改写宿主自己的界面。

飞书 `client.ts` 的普通发送、回复、私信、临时卡片、消息更新及三种卡片流式写入是所有正文的共同出口，宿主写的正文也经过这里，因此这里只检查卡片链接字段（`linkFieldContext`）：指向本机的链接字段按下文形状放行，其余拒发；正文原样发出。宿主生成的会话结束卡恢复命令、`/status` 的 Terminal 与 CWD、adopt 选择卡、worktree 清理卡、流式卡终端快照，以及 `/dashboard link` 私发给管理员的管理首页链接都不改写。其他由模型直接调用、写入飞书的命令（如 `botmux card stream`）不在上述入口内，正文不替换，与引入本策略前一致。outbound hooks 与已发布群上下文记录使用实际发送的展示副本。

`cot-message.ts` 的原生思考消息走单独的 API。它只处理完整 reasoning 节点、工具标题和可见工具结果，保留工具 args 与 AG-UI 身份字段。

`botmux send` 在 link-ref 展开后处理正文、准备文本、自定义卡片和完成提案，随后再校验、上传、记录发送账本。自动 final 在冻结投递正文前处理；unified 回复卡的渲染、发送、PATCH 与自动生成的长回复附件也处理；worker 断开或 daemon 重启后结算回复卡时，记录里保存的是模型原文，重新渲染的卡片和补发的附件同样处理，重启时按会话记录取工作目录。冻结记录重放仍经 SDK 出口的链接字段检查，已校验正文自身的链接按下文沿用。自动文档评论会话在分块前处理回复正文，一般文档工具的执行输入不变。

完整规则每个会话只给一次：自建 botmux 系统提示的 CLI（claude-code、genius、grok、pi、oh-my-pi）放在系统提示里，不注入会话上下文的 CLI 放在新话题首条消息的 Shell 提示里。每轮飞书格式提示只带一句提醒，mira 与无传输会话不带这层提示。例外：dsh、codex-app、mira、mir、mojo、riff 自己注入会话上下文但不使用 botmux 系统提示，两处都拿不到完整规则；这与 master 上其余路由规则的投放一致，本 PR 不改。定制中心按运行时实际读取的键登记：完整规则 `ai.routing.no_local_addresses` 在「会话开始」，每轮一句 `ai.followup.no_local_addresses` 在「每条新消息」。零注入与 HTTP 程序输出仍保持既有语义，进入飞书时按所经的入口处理。

## 投递失败与兼容性

本机跳转拒绝发生在 provider 写入之前，发送账本按没有外部副作用处理。自动 final 记录结果不可用、发送固定说明并停止原样重试。未捕获的同类错误由公共投递 coordinator 持久标记为拒绝。既有 provider UUID 与 receipt 规则保留，拒绝说明使用独立且稳定的去重键。unified 回复卡遇到该拒绝直接失败，不按瞬时错误退避重试。

默认局域网或自托管部署未配置公网 external host 时，宿主自己构造的页面链接指向本机网卡地址。卡片链接字段只放行这些链接的形状（`src/core/host-capability-link.ts`），判定只看 URL 与配置（Web 终端和 Dashboard 的 external host、Dashboard 端口），不依赖进程内状态，daemon、`botmux send` 进程和重启后的 daemon 结论一致。例外是 HOME 被隔离的沙箱：其中的 `botmux send` 读不到 `~/.botmux/.dashboard-port`，只认配置的 Dashboard 端口（`BOTMUX_DASHBOARD_PORT`，默认 7891），Dashboard 因端口占用改用其他端口时，模型在沙箱内发送的 Dashboard 链接会被拒发；宿主进程发出的卡片不受影响。放行的形状是：任意端口上的终端会话页 `/s/<id>`，以及 Dashboard 端口以外带单个能力参数（`token` 或 `viewToken`）的终端根页；Dashboard 端口上的首页（可带 `t`）、白名单前端路由（v3 运行详情、工作流、会话、工作台）、`/workbench`、可信插件结果、工作流入口与决策看板事项路径。飞书客户端打开链接（`applink…/client/web_url/open`）只按其 `url` 参数里的目标判断。其他端口、其他路径与路由、多余或格式不符的参数、含用户信息的 URL，以及模型自建卡片里的其他本机链接仍拒发；同形状的链接即使由模型拼写也会放行，背后的页面仍按会话、能力参数或登录鉴权。只读终端链接是不带能力参数的直连端口时（如会话卡在终端代理端口绑定失败时的直连地址，或 worker 未上报只读能力），流式卡、状态卡与会话卡省略该终端按钮，卡片其余部分照常发送。本机自拼的 origin 统一由 `localHttpOrigin` 构造。形状放行只作用于链接字段；模型输出入口的正文里，同形状的本机链接仍会被替换。

先校验、再落盘的正文在重放时沿用自身链接字段里的本机目标（`replayVettedBody`，只作用于这一次发送）：自动 final 的 handoff 与输出日志冻结正文，以及 unified 回复卡启动恢复时重放的 PATCH。这些正文写入前已经过同一策略，Dashboard 端口或主机在重启后变化时不会被永久拒发；沿用只覆盖正文自身带的链接。

策略属于飞书公共展示层，不依赖 CLI 类型、PTY/tmux 后端、会话新旧、沙盒或 replyDelivery 模式。上传源路径和原始转写继续保留其执行与排查用途。

## 验证

行为测试覆盖真实 SDK 写入边界（正文原样发出，含局域网部署下的会话结束卡、流式卡终端快照、`/status` 文本、worktree 清理卡与 `/dashboard link` 的私信和临时卡片）、系统路径豁免及其反例、跨平台地址、按钮拒绝、局域网部署下各类宿主链接放行（含 v3 卡、其他 bot 的会话卡、飞书侧边栏包装、未经本进程构造的链接，以及大量终端链接之后的 Dashboard 链接）、同主机其他路径、路由、参数与端口仍被拒、包装或多层编码里嵌套的本机地址、Dashboard 换端口后重放冻结正文与启动恢复 PATCH、其他进程写入的终稿卡、缺少只读能力时只省略终端按钮而卡片照常发送、合法业务 URL、回调/媒体保留、流式片段、投递重试、账本拒绝、unified 长回复附件、回复卡断线与重启后的重新渲染及补发附件与文档评论桥接。

独立异常探针使用真实组件与假时钟覆盖：重试等待中关闭会话、前半步已落盘后重放、重试窗口与恢复 tick/heartbeat 交叠。摘掉任一模型输出入口（`botmux send`、自动 final、回复卡、CoT、文档桥接）的正文处理，或传输层的链接字段检查，均使相应用例失败。

变更以独立分支交付。切换线上 checkout 前应先确认当前线上包含的其他修复已被保留，再构建并重启；历史已发送的消息不会自动改写。
