# 群聊上下文共享

用户在同一群的主对话或同一话题里只点名一个机器人进行讨论，随后向另一个机器人提问时，后者应自动获得该会话范围内的背景。主对话与各话题隔离，不自动补入其他话题；普通引用回复仍按实际位置归属。旁听本身不启动 CLI，不改变现有提及、授权和任务路由规则。

## 控制与范围

真人管理员通过 `/context-sharing on|off|status` 为当前群设置一次开关，默认关闭。命令无需创建模型会话；复用严格的管理员身份与群类型检查，私聊、未知群类型、仅有会话授权的用户和机器人都不能修改开关。

设置按群共享，观察记录按应用与群隔离。每个应用只通过自己的消息事件和历史 API 读取群内已发布内容。私聊、模型推理、未发布工具输出不进入日志。历史附件只允许应用凭据读取，不回退到历史发言者的个人 OAuth。

## 观察记录

`group-context-ingest` 在消息的 self/mention 早退之前旁听；编辑事件在权威回读、确认群类型之后记录，任务早退规则保持不变。成功的发送回执也记录正文，避免依赖平台回送自己发出的消息。

`group-context-store` 使用现有 Node/Bun SQLite 兼容层。消息 ID 幂等，正文/附件变更追加本地序号与 revision，补全发送者名称不增加 revision。平台提供更新版本时拒绝更旧正文；撤回是终态，且优先于正文版本比较。

默认保留 30 天、每群 10,000 条；淘汰明确留下缺口。写入争用有短时限，失败不能阻断正常消息处理。目录和数据库采用私有权限。

卡片共享以对话正文为单位：启动、排队、工作状态、工具过程、用量和控制按钮不进入新记录；正式答复、补充内容和待回答问题保留。统一回复卡通过结构标记分离正文，先投影再解析文本及附件，成功 PATCH 也会更新记录。旧运行卡正文在读取时过滤，不能确认结构的历史卡片暂时省略并标出缺口。普通用户文字或第三方卡片不按状态关键词过滤。详见[卡片正文设计](2026-10-06-group-context-conversation-only.md)。

## 每轮自动补齐

在已授权的普通激活入口准备背景，包含带正文的 `/t` 类指令和配置的任务触发词。原生命令不为此产生模型回合。历史回查使用应用自己的权限、分页上限与超时；温热状态以完成的历史查询作为边界，不能把刚收到的当前消息当成缺口已补齐的证据。

背景组合为最近原文、较早消息的有出处摘录和问题匹配的旧来源。中文查询先分词，拉丁词保留边界；不调用额外大模型把同行建议加工成“用户确认”。每条记录保留发送者、话题和消息 ID，内容作为不可信引用转义。长记录的字符预算、附件不可读、订阅未知、保留期或扫描上限都会产生明确的不完整标记。

来源必须先通过主对话／当前话题的归属筛选，才进入附件读取和内容排序。root_id 只是回复关系；原生 thread_id、明确的发送目的地和真实话题容器读取共同提供归属证据。详见[会话范围设计](2026-10-06-group-context-conversation-scope.md)。

新消息的截止点是当前触发消息；有版本的未来编辑以及无法判定时间的后到编辑不会混入更早的请求。撤回优先消除文本。每轮生成的背景包按应用、群、turn 固定，重试复用相同内容，不吸入随后发生的讨论。

统一卡片缺少平台编辑时间时，另存首次看到该正文的 `cardObservedAt` 作为保守截止界限；它不参与平台版本排序，重复读取同正文也不推动该界限。每轮从 SQLite 读取有界记录，覆盖同序号元数据补全及其他进程写入。

## 交付与恢复

普通首轮、续轮和恢复输入使用独立背景块；Codex App 的正文仍是原始用户请求，历史进入 `untrusted additionalContext`，相关图片可作为原生图片输入。接管会话保持原有轻量桥接形式。`promptInjection=none` 和无 IM 输入保持原行为。

交付账本区分准备、绑定、实际派发和确认。worker 入队不代表模型接收；绑定同一应用、群、turn、会话、原生 epoch 和 worker generation 后，精确的原生输入消费证明可提前确认具体来源序号，成功完成回执保留作兜底。不用最大序号越过尚未覆盖的记录。缺少连续性证据时重复提供有界背景，不静默跳过。已交付表示输入中提供过，不表示模型永久记住，也不表示它读过被摘录省略的文字。

同一原生会话采用增量交付：确认过的具体版本不再以短摘录重复注入，没有新来源时整个共享块为空。正常对话收到的用户输入和本轮成功发布的模型答复/提问也纳入确认覆盖；编辑、撤回仍作为新版本提供。快照按原生 epoch 隔离，确认覆盖独立于快照数量上限保存。详见[增量交付设计](2026-10-06-group-context-incremental.md)。

## 撤回订阅

新应用的可选事件清单包含 `im.message.recalled_v1`。已有启用群的应用在启动或首次使用时执行合并的、非阻塞的增量订阅检查；关闭功能的部署不因此新增检查。

健康状态区分已存在的订阅配置、提交但尚需发布的更新、登录态不可用、未知和过期。命令输出及背景缺口使用同一健康记录。配置回读通过不等于每次平台推送都必然到达；不得把待发布状态当成已覆盖。

## 验证范围

- 真实 dispatcher → 记录 → 自动准备 → Codex 输入组装的组合用例：仅点名另一机器人讨论和更正，本机器人保持静默，最后一次被点名时只激活一次并获得来源链。
- 重复消息、编辑排序、撤回竞态、跨应用/群隔离、数据库重开和并发写入。
- 默认关闭、私聊拒绝、权限拒绝、首轮/续轮、结构化输入、接管桥接、原生命令与零注入模式。
- 历史超时、截断与保留期、旧中文约束检索、10,000 条记录预算、附件应用权限拒绝。
- 不可变重试、错误会话/epoch 回执、乱序确认、订阅配置与公开状态。

平台权限、事件发布状态以及历史 API 不提供的版本信息仍是外部限制；通过状态和输入缺口显式表达，不以本地测试代替线上验证。
