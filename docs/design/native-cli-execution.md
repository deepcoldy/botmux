# 原生 CLI 与任务控制权

完整原生模式要求关闭全部触发人鉴权能力，并显式关闭 `larkToolBinding`。CLI 使用宿主已有的登录和默认应用；BotMux 不替原生 CLI 切换平台用户。受管模式的凭据缺失或部分能力关闭不构成原生模式，也不触发原生回退。

调度创建与执行根据控制人、当前操作权限、群成员关系、任务权威、授予范围和撤权状态判断。完整原生模式可以创建及运行同话题一次性子任务和已授权的委派任务；受管模式仍要求完整个人工具隔离。原生 CLI 的权限来自宿主登录，不应将 `runScopes` 解释为对宿主账号每条命令的隔离保证。

进程证明继续复用当前执行的 socket/PID/出生标识和 worker 代次，不依赖 CLI 包装器是否存在。现有 worker 已通过会话结构计算证明模型，计算时不使用应用绑定开关。后台登记仍保留原有 Linux、任务、控制人、进程血缘、到期和撤权限制；后台请求观察到配置策略变化后会永久退役旧登记。沿用基线的内容哈希检查，不承诺无人请求期间的配置往返也主动退役登记。

worker 在真实启动入口报告 CLI 模式和系统执行账号。当前执行查询通过显式字段选择返回该报告，同时核对 worker 代次和当前配置；旧 worker、模式切换尚未重启或报告缺失时返回 `unknown`。该系统账号是进程执行者，平台账号仍由原生 CLI 的登录配置决定。当前 Actor 表示发起/控制人，两者不能混为一人。

原生定时轮的控制人证明独立于个人工具凭据发布。只从宿主任务权威取得已重新核验的控制人，并绑定精确 scheduled turn；不写入 task owner，不授予创建后代、跨话题或其它任务操作权限。受管工具路由不使用原生控制人证明来签发个人凭据。

个人宿主操作的调用者需同时取得当前执行模式和宿主操作权限证明；不能通过删除 `BOTMUX`、替换 PATH 或提交任意身份 JSON 宣称原生模式。默认查询的协议保持不变，只有请求新增字段的客户端接收模式信息。

验收覆盖原生与受管模式、部分配置、旧 worker、代次及模式切换、控制人撤权、任务暂停/恢复、一次性完成与重放、跨群/话题和后台进程血缘。所有测试使用隔离 HOME、私有进程与假数据，不访问真实用户凭据或宿主任务。
