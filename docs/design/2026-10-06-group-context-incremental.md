# 群聊共享按已确认版本增量交付

同一个持续的原生会话只自动补入未交付的消息版本。没有新增来源时，不生成共享历史块，也不重新下载历史附件。模型对已有上下文的理解和客户端的压缩不由 Botmux 用重复摘录干预。

## 交付范围

- 精确记录应用、群、Botmux 会话、原生会话 epoch 和消息 seq。seq 标识本地消息修订；最大 seq 只表示快照边界，不能用来跳过中间遗漏的来源。
- 已确认的共享来源直接排除，不再渲染 `previously_delivered` 短摘录。编辑和撤回生成新 seq，仍可交付；先选同一消息最新修订、识别有效撤回，再按覆盖集合筛选，避免旧版本复活。
- 当前正常输入在异步历史查询前捕获精确版本。成功发布的模型答复及初次提问也记录对应版本，避免这些原生对话下一轮再次作为群历史注入。不能按“发送者是自己”粗略排除，因为另一个会话的同名 Bot 仍可能需要这些内容。
- 准备、排队和发布回执都不替代原生输入消费证明。绑定正确的应用、群、turn、会话、原生 epoch 和 worker generation 后，精确原生历史／全文转写匹配或被接受的 RPC 输入回执可提前确认；成功完成回执保留作兜底。确认覆盖实际派发的背景、精确原生输入及本轮已登记的成功发布版本；确认后的迟到发布回执仍可补充版本。缺乏正向归属或消费证据时允许重试，不把未送达内容当成已读。

## 会话和重试

输入快照按原生 epoch 隔离，同一 epoch 的同一轮重试保持不变。另一原生会话重试相同消息时重新准备有界历史，不能复用旧会话已经过滤过的空背景。

准备时冻结来源片段，实际发送前只扣除当前已经覆盖的来源及其附件，不重选候选或扩大预算。首次实际派发结果另存快照，重试和后续回执都以它为准；若 payload 中找不到对应共享块，不落派发快照。正文变化时同步更新 Claude hook sidecar 的指纹与前缀。

新进程在实际分配 worker generation 时绑定输入，而不是把组装输入时的旧进程编号当作执行证据。首次尚无原生 ID 的临时 epoch，只有拿到与该输入进程相符的真实原生会话身份后才能提升；原生消费回执或成功完成路径均可完成这一步。仍未解析到真实原生 ID 的临时 epoch 不接受早期消费确认，保留完成路径兜底。记录转换的前驱身份，允许此前已发出、稍后才返回的成功发布回执归到同一轮；其他进程的迟到回执不得借用。

已确认的来源覆盖与冻结输入快照分开保留。清理旧快照不会让仍在保留期内的已交付消息重新变成新增。覆盖沿用 30 天保留边界；不同原生会话不继承覆盖。

## 限制

- 覆盖表示该版本的原文或摘录已提供，不表示模型永久记住全文。被节选省略的细节可以通过 history/quoted 按需读取，不靠每轮重复旧摘录补足。
- 缺乏连续性或交付证据时宁可重复，不能把未送达内容当成已读。新会话需要新的历史基线。
- 同一轮准备后的新消息仍等下一轮补入。没有新来源时，缺口状态留在诊断元数据中，不单独生成一段重复背景。
- 不改变共享开关、权限、暂停期间回补策略、群历史访问范围或模型工具授权。

## 验证场景

覆盖首次分享、无新增时空输出、新消息、消息编辑/撤回、未覆盖序号缺口、失败交付、正常输入和自有回复去重、附件去重、首轮原生 ID 建立、进程恢复、同请求跨 epoch 重试、发布回执延迟、跨应用/群/会话隔离、数据库迁移和快照淘汰。
