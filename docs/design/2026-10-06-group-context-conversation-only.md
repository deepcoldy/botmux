# 群聊共享只保留对话内容

## 已确认的范围

运行状态、排队、启动、工作中、工具过程、用量、终端控制和无最终答复占位不进入共享正文。正式答复、补充消息、有内容的阶段结论以及向用户提出的问题仍可共享；是否使用卡片承载不是准入条件。统一回复卡从运行状态转成正式答复时，只共享正式正文及其附件引用。

本次不更改群开关、关闭时间段是否回补、路由、模型任务互斥、Dashboard 或终端 CLI。保留现有消息修订、撤回、默认关闭及有界历史策略。仅本地实现和验证，不推送远端。

## 设计

1. 在卡片生成层给运行区域和对话用途显式标记，复用合法的 element_id，保留正式卡片自己的元素 ID 和视觉布局。统一回复卡的状态、过程、用量和控制均与正文分离。待回答的问题和选项属于对话正文。
2. 新增共享专用卡片投影器，返回 runtime / conversation / unresolved / 普通未标记卡片。正常 history、quoted 的完整卡片解析维持原有行为。共享路径先投影结构，再解析文本和资源，避免 A/B 卡片合并把状态混回正文。
3. 实时事件、成功发布回执、历史列表及卡片详情回补共用同一投影器。简化格式丢失标记的统一卡片必须补取结构；无法确认时省略并报告不完整，不直接保存进度正文。补取后的更新时间也必须来自详情，不能沿用较旧的列表时间。
4. 正式卡片优先使用平台更新时间，不沿用最初状态卡创建时间。平台未提供版本时，将本地首次观察写入独立的 `cardObservedAt`，用于保守限制进入哪一轮背景，不能冒充平台版本参与新旧比较；相同正文的再次观察保留原有时间界限。仅观察成功发送/更新，失败不得生成已发布正文。
5. 已入库的旧统一状态卡记录不能再次进入模型输入。为规范化卡片保存投影版本；旧运行卡特征只作范围严格的兼容识别，普通用户文字和第三方卡片不按关键词过滤。撤回先于去重/过滤处理，真实答复的撤回仍保留。
6. 同正文补全投影版本或时间信息不新增消息序号。每轮重新读取有界 SQLite 记录，避免只按最大序号缓存时漏掉实时事件或 CLI 子进程的元数据补全。

## 兼容边界

- CLI 明确指定 `--response-kind progress` 的独立卡片标为运行状态；`final` 和 `auxiliary` 标为对话。需要共享有实质内容的中间结论时使用 `auxiliary`。没有声明用途的历史发送保持兼容，不靠“正在”等关键词猜测正文性质。
- 新统一卡片通过签名页脚的不可见用途标记和运行区域 ID 区分正文。简化历史视图缺少区域结构时回取结构化详情；取不到时省略并标缺口。
- 旧的已落盘状态正文不会批量删除；已知运行卡形态在读取时过滤，能取得结构化正式正文时追加修订或补全投影元数据。既有模型会话已经收到的内容以及已经冻结的旧轮背景不会被收回。
- 暂停期间是否回补、关闭时取消在途同步、关闭期间撤回对账、任务分工互斥均不属于本次修改。

## 验收

- 启动、工作、失败但没有正文的卡片不入共享正文；普通文本中出现 Working、Completed、正在工作等词不受影响。
- 同卡状态转正式答复后仅保存正文/正文附件；运行中的正式 final 也可共享，不能只认已完成标签。
- 问题及选项可共享，按钮回调、工具结果、状态、用量不共享。
- 正式答复之后仅状态或用量刷新不制造正文修订；旧进度不能覆盖正式答案。
- 结构化详情优先于简化视图；正文和资源来自同一投影；同轮截止时间排除未来更新。
- 既有状态记录不重新注入；普通真实消息的修订、撤回和交付游标保持正确。
- 相关测试、编译和本地部署检查通过后才报告完成。
