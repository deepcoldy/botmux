# 显式收件人与卡片寻址

`botmux send --mention <标识>:<显示名>` 指定本条消息的收件人。Card 2.0 的 `markdown` 和旧版 `lark_md` 节点中的对应 `@显示名` 会转换为真实 mention；已经在正文出现的收件人不会在 footer 重复展示。

存在显式收件人时，默认 footer 的 owner/caller 寻址让位：oncall 群不再额外 @ 本轮触发者，非 oncall 群也不再额外 @ 会话 owner。该规则同时适用于显式指定真人和机器人；需要通知 owner 或触发者时，将其加入显式收件人（`--mention` 或 `--mention-back`）。未指定显式收件人时，保留默认寻址。

显式收件人不包含触发者时，同时取消隐式引用；显式 `--quote` 或显式包含触发者时保留引用关系。

开启 `allowArbitraryMention` 后，邮箱等标识的通讯录查询未命中时，可按目标群成员的唯一精确显示名兜底。重名、查无此人、读取成员失败都会拒绝发送，退出码为 2。解析结果仍须通过目标群成员检查。

读隔离的 managed CLI 无法读取宿主 `bots.json` 时，通过现有的 nonce 绑定、宿主写入的来源证明取得所属 bot 的 `allowArbitraryMention`。权限默认关闭；旧证明缺失该字段时也保持关闭。可写的 `send-cred.json`、环境变量和 IPC 响应正文不能开启权限。每次发送请求前重新获取证明，若所属应用变化或权限已撤销，拒绝后续发送请求。已经确认送达的主消息保留权威回执。宿主 outbox relay 和普通发送继续读取宿主 bot 配置。

`test/cli-send-member-mention.test.ts` 执行真实 CLI，并以 SDK 请求适配器替换外部网络，覆盖唯一姓名成功发送、重名、缺失和群外成员拒绝，以及读隔离下的权限证明、伪造字段与中途撤权。这验证发送接线与出站内容，真实飞书客户端展示需另行验收。
