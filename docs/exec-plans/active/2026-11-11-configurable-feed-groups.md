# 插件可配置个人消息分组

分类名称与切换策略由插件配置管理。宿主增加通用的、有明确分组范围的接口，保留现有单数路径供旧插件兼容；不在宿主增加任何新分类枚举。新插件使用独立路径，旧宿主会拒绝该路径，避免忽略清理范围后误删其他分组关联。

```mermaid
flowchart LR
  A[插件命令] --> B[读取并校验配置快照]
  B --> C[目标名与清理范围]
  C --> D[宿主鉴权与发令人 OAuth]
  D --> E[先加入目标分组]
  E --> F[只移除范围内的其他分组关联]
```

## 功能与文件

- `src/services/chat-feed-groups.ts`：有界名称与范围校验、限定范围的先加后删；保留旧调用合同。
- `src/core/dashboard-ipc-server.ts`：新增 `PUT /api/groups/:chatId/feed-groups`，强制提供 `managedLabels`。
- `test/chat-feed-groups.test.ts`：自定义名称、范围隔离、无效配置无写入、部分失败、权限与身份测试。
- 独立 group-rename 插件：可配置四个默认分组、互斥与关闭清理；固定快捷命令和通用 `/label <key>`；运行时配置重读及原事件去重、水位保留。

## 合同

请求为 `{ actorOpenId, label: string | null, managedLabels: string[] }`。名称区分大小写，不允许空白首尾或控制字符，每个至多 50 个 Unicode 字符，最多 50 个不同名称。非空目标必须属于范围；空范围加 null 为无写入清理。只操作发令人在当前应用下可管理的个人分组，不借用 owner 授权。所有参数在凭证解析及网络访问前校验。

新路径与旧路径共享既有串行队列、鉴权、超时和取消逻辑。新增调用不影响其它 IM、CLI、PTY/Tmux、话题/群会话、sandbox 或 workflow 的执行路径。

## 验证计划

先跑针对性行为测试，再执行类型检查与构建。独立复核配置变更、部分写失败与过期关闭事件交叠。交付宿主 PR 与独立插件包；不自动重启全部机器人或替换运行中宿主。

## 已完成的验证

- 定向 7 文件 172 项通过，覆盖个人身份与旧 owner token 隔离、范围限制、命令网关/关闭通知、未绑定 Bot 拒绝与 malformed JSON。
- 插件 `npm test` 48 项通过；新增配置 CLI，使用宿主已有 `api.config.replace` 校验后原子保存。运行时每条新命令读取配置，已完成事件先重放持久结果。
- 组合真实 handler 与 `replaceChatFeedGroups` 的围栏探针覆盖在途配置快照、部分删除失败后的新事件修复与重启、禁止关闭清理的水位、旧宿主 404 不回退。
- 复核发现配置读取早于去重，导致改配置后重复事件未返回原结果；已调整为先重放事件，再读取新命令的配置，并补回归。
- 复核发现无效配置下的关闭未写水位，可能让延迟旧分类命令恢复关联；已将失败选择也经过串行水位记录，但不执行外部修改，并补跨重启回归。
- 水位守卫变异后，组合探针在旧关闭清除了新分类时失败，确认覆盖有效。

运行环境保持 Botmux 3.59.1 与插件 0.2.0；新插件必须先有新宿主接口，不自动部署到现有机器人。
