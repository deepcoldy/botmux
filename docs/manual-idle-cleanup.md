# 手动清理空闲会话

会话控制页的“清理空闲”提供 `1H`、`24H`、`72H`、`7d` 和“全部”。
默认仍为 `24H`。时间档位选择最后聊天活动早于该时间的会话；“全部”取消
时间限制，也包含没有最后活动时间的空闲/休眠会话。

清理范围仍受页面当前筛选条件约束，确认前显示的数量与请求提交的会话 ID
一致。所有档位均保留原有保护：仅处理空闲或休眠会话，跳过运行中、启动中、
已关闭、锁定、有待处理仓库、TUI 提示或 attention 的会话；待办池里尚未开工
（暂存了草稿）的会话也不会被清理，「全部」同样不例外。仍在提供终端端口
的休眠会话不进入清理范围。执行沿用既有后端关闭、回收及 adopt 断开语义。

API 的 `olderThanHours` 支持 `1`、`24`、`72`、`168`、`0`；其中 `0` 表示
全部可清理会话，字符串 `all` 也可使用。空值、布尔值、对象和非支持的时间
均被拒绝。时间边界仍为严格“超过”，正好空闲一小时的会话不属于 `1H`。

定时自动清理保持原来的 `24H`、`72H`、`7d`，默认七天，未增加“全部”档位。

## 已知边界：激活在途的待办

待办会话被激活时，worker 一开始拉起 CLI 就会先清掉行上的 `queued` 标记，
进入 `queuedActivationPending` 在途状态，直到激活 ACK 持久化完成。若 worker
在 ACK 前退出，或 ACK 持久化持续失败（该写入会指数退避无限重试），这一行
不再带 `queued` 标记，因此上面的待办保护识别不到它：在「全部」档下可能被
计入清理；在 `1H`/`24H`/`7d` 档下，若最后活动时间早于阈值也可能被计入。
被关闭后再恢复会清掉暂存的 `queuedPrompt` 草稿正文。

触发需要 worker 在激活 ACK 前退出或 ACK 持久化连续失败，窗口通常很短。
注意从 Dashboard 点「开始」或把会话拖到「进行中」触发的激活不会刷新最后
活动时间，因此一条很久以前入池的草稿一旦卡在在途状态，各档位（含 `7d`）
都可能够格；群消息触发的激活会先把最后活动时间刷新为当前时间，那种情况
下通常不够格。清理弹层的计数和确认清单会如实列出这些行，单个会话始终
可以用单会话关闭等显式操作处理。要彻底排除这类行，需要在 Dashboard 行上
额外投影激活在途信号，留作后续改进。
